> **규범 문서.** 버전마다 무엇을 통과해야 내는지 (2장), 성숙 단계에 들어가는 조건 (3장), 안정화 버전의 기준 (4장), RC (5장),

## 1. 기준 틀 (버전마다 같은 여섯 칸)

```text
기능       그 버전 태스크 (releases "태스크" 줄) 의 완료 기준이 자동 시험 또는 기록된 수동 QA 로 확인됨. 통합 시험 태스크가 있으면 그것 포함

호환       번호를 올린 버전은 versioning 5장 · audit/VERSION-MIGRATION-MATRIX 갱신, 옛 것 읽기 시험
```

## 6. GA (v1.0.0) — 차단 조건 · 최종 승인 (RH-24-5)

### 6.1 차단 조건 (하나라도 있으면 v1.0.0 을 붙이지 않는다)

```text
데이터     세이브 · 패키지 · 설치 · 마이그레이션의 손상 · 손실 재현 사례가 열려 있음 · 복구 훈련 실패 · 백업 없는 서비스 데이터
보안       외부 감사의 높음 이상 미해결 · 24 1장 의 "예" 행 중 시험 기록이 없는 것 · 서명 없는 릴리스 · 업데이트 · 레지스트리
결정론     골든 · 리플레이 해시의 이유 없는 변화 · 툴체인 간 재생 불일치
안정성     긴 Soak 의 충돌 · 자원 증가 추세 · Sanitizer 보고 미해결 (억제 목록에 이유 없는 줄)

제작자     외부 제작자 게임 E2E 실패 · 외부 시험 P0 (데이터 손실 · 충돌 · 진행 불가) 미해결
```
