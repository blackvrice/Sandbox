# 24. 보안 · 안정성 출시 기준 (v0.5 ~ v1.0) — 위협 · 모듈 · 검증 · 버전 · 릴리스 차단

> **계획 · 규범 문서** (2026-11-02, master c651339). 버전마다 "이것이 통과하지 않으면 그 버전을 내지 않는다" 를 적는다. 설계는
> [22-RUNTIME-V2](22-RUNTIME-V2.md) · [ADR-0086](adr/0086-runtime-architecture-v2.md) · [ADR-0088](adr/0088-v06-v10-placement-update-runtime-v2.md),
> 작업은 [23-ROADMAP](23-ROADMAP.md), v0.5 의 자세한 차단 조건은 [20](20-CREATOR-ALPHA.md) 13.2 (이 문서가 대신하지 않는다 — 더한다).
> 초안의 보안 설계는 [platform/architecture/11](platform/architecture/11_SECURITY_AND_TRUST.md) (동결). 상태: **현행** = 시험이 있다
> (이름), **[계획 vX]** = 그 버전에 만든다.

> **2026-11-03 로드맵 재구성 ([ADR-0096](adr/0096-roadmap-versioning-small-milestones.md)):** 이 문서의 버전 표기 ("[계획 v0.x]" · "v0.5 M6" …) 는 옛 줄이다 —
> 목표 버전 · 상태의 정본은 [roadmap/task-registry](roadmap/task-registry.md), 읽는 법은 [versioning 4장](roadmap/versioning.md). 태스크 ID 는 그대로.
> 2장 "버전별 릴리스 차단" 은 [roadmap/release-gates](roadmap/release-gates.md) 2장이 새 버전에 다시 놓았다 (1장의 위협 행은 그대로 정본).
> 위협 행 전부의 재확인 · 퍼저 · 공급망 · 계정 보안 시험은 v0.23 ([stabilization](roadmap/stabilization.md) 2장), GA 차단 조건은 release-gates 6장.

## 0. 원칙

```text
S1  스크립트 · 패키지 · 네트워크 입력 · 세이브 · 리플레이는 모두 신뢰하지 않는 입력이다 — 검증한 뒤에만 시뮬레이션에 닿는다
S2  권한은 Capability (22 3.2) 로 좁게 — 기본은 없음. 외부 OS · 파일 · 네트워크 접근을 스크립트에 주지 않는다 (NetworkModule 은 허락
    목록 · 할당 · 서버만)
S3  모든 예산은 결정적으로 넘친다 (트랩 또는 버리고 계수) — 서버가 멈추거나 메모리가 끝없이 늘지 않는다
S4  "통과" 는 실제로 돈 시험만. CI 와 로컬을 나눠 적고, 돌리지 않은 환경은 "검증 안 됨" (13 8장)
```

## 3. 안정성 기준 (보안과 같이 본다)

```text
충돌     매 버전: 자동 플레이 (sample_*) · 퍼즈가 충돌 0, 충돌 보고 묶음이 남는다 (M1)

호환     .sbc · Host API · 프로토콜 · 세이브 · 패키지 번호를 올린 버전은 읽기 호환 표 (12 platform · 09) 를 갱신
```
