# Sandbox 0.2.0 — Game Creator (2026-10-21)

> **이력 문서** (바꾸지 않는다 — 다음 버전은 새 파일). v0.2 의 계획 · 마일스톤은 [18-PLATFORM](../18-PLATFORM.md) 5장,
> 요구사항의 출처는 [플랫폼 설계 초안 roadmap/v0_2](../platform/roadmap/v0_2_GAME_CREATOR.md). 제품 버전 = CMake `project VERSION 0.2.0`.

## 1. 한 줄

코드 없이 템플릿으로 미니게임을 만들고 (sbx new) → 편집 · 테스트 플레이하고 → 게임 패키지로 빌드해 (sbx build) → 헤드리스 서버와
로컬 플레이에서 같은 결과로 끝까지 돌린다. 데모: [samples/rabbit_guard](../../samples/rabbit_guard/README.md) "토끼 지키기".

## 2. 들어간 것 (마일스톤 · ADR)

```text
M1 GameProject      매니페스트 sandbox.project.json (schemaVersion 1 · 2) · SemVer · 검사 P1~P5, --world <프로젝트>, 핸드셰이크
                    게임 정체성 (프로토콜 8), sbx new · check · templates, 프로젝트의 세이브 = <프로젝트>/worlds   ADR-0040~0044
M2 GameMode         modes/*.json (V8) · game.session (단계 17b — Lobby · Starting · Running · Finished) · GameControl · 재시작
                    (시작 월드 다시 열기 · 자동) · "게임" 패널 (프로토콜 9)                                         ADR-0045 · 0046
M3 Feature Bundle   PlayerAction (actions.json V9 · 명령 · "행동" 패널, 프로토콜 10), 점수 game.score · 팀 태그 · 끝 조건
                    score · 스폰 지점, 게임 키 (팩 presentation/input.json) · 카메라 처음 자리 · 데모 모드 eco.protect · sbx new
                    --mode                                                                                        ADR-0047~0049
M4 Visual Trigger   triggers/*.json — 노드 종류 표 21 종 · 나무 그래프 → 실행 표현 (V10 · 재진입 경고), 단계 17c 실행 (스냅숏 ·
                    같은 틱 이어짐 · 예산), "콘텐츠" 창의 트리거 폼 · 오버레이 종류 Trigger (프로토콜 11)                 ADR-0050~0052
M5 Edit ↔ Play      테스트 플레이 (편집 월드를 서버 메모리에 맡기고 복사본으로, 멈추면 그대로 — 프로토콜 12), 게임 패키지
                    .sbpkg (SHA-256 · digest · 같은 프로젝트 = 같은 바이트, sbx build · check, --world <패키지>), 세이브 결속
                    (world.json "game")                                                                           ADR-0053 · 0054
M6 E2E              samples/rabbit_guard · 자동 플레이 스크립트 (--script) — 헤드리스 서버 = 로컬 플레이 (프로젝트 · 패키지 모두),
                    --exit 는 게임이 끝나도 끝낸다                                                                  ADR-0055
```

## 6. 알려진 문제 · 열린 검증

```text
- Windows 의 CTest 는 chcp 65001 (UTF-8 콘솔) 뒤에 돌린다 — 아니면 CMake 가 도구의 UTF-8 출력을 cp949 로 읽어 project_* ·
  net_server_probe_* 의 정규식이 맞지 않는다 (도구 문제가 아니라 시험 실행 환경)
- render_tests_warp: 이 개발 PC 에서 D3D12 Debug Layer 의 배리어 메시지로 "render tests OK" 가 나오지 않는다 (doctest 28/28 통과,
  v0.2 는 render 를 건드리지 않았다) — v0.1 의 실기 QA 항목과 함께 본다
- samples/rabbit_guard 의 기대 해시는 MSVC 키만 기록했다 — 다른 툴체인에서는 해시를 보지 않는다 (서버 = 로컬 비교는 한다)
- v0.1 의 열린 항목 그대로 (18 1.1): Windows · Linux · macOS 실기 QA, 50k 판정, GitHub Actions 결과
- 네트워크는 LAN · 신뢰 환경 전용 (R6 — 암호화 없음)
```
