# Sandbox 0.4.0 — Package Manager (2026-10-28)

> **이력 문서** (바꾸지 않는다 — 다음 버전은 새 파일). v0.4 의 계획 · 마일스톤은 [18-PLATFORM](../18-PLATFORM.md) 6.4 · 6.5,
> 형식의 규범은 [09-SERIALIZATION](../09-SERIALIZATION.md) 9 ~ 12장, 요구사항의 출처는
> [플랫폼 설계 초안 roadmap/v0_4](../platform/roadmap/v0_4_PACKAGE_MANAGER.md). 제품 버전 = CMake `project VERSION 0.4.0`.

## 1. 한 줄

콘텐츠 팩이 곧 패키지다. 다른 제작자의 팩을 로컬 폴더 · Git 태그/커밋에서 받아 (`sbx add`) 의존 그래프를 풀고 (팩마다 한 버전 —
소스가 곧 버전, 범위는 확인), 잠금 파일 `sandbox.lock` 으로 고정해 `.sandbox/packages` 에 트랜잭션으로 설치한다. 게임 스크립트는
`import … from "@<팩>/…"` 로 패키지의 컴포넌트 · 함수를 쓰고, 같은 잠금이면 다른 폴더 · 빈 캐시에서도 같은 game digest 가 나온다.
나쁜 패키지는 설치 전에 거절되고 프로젝트는 바이트 하나 바뀌지 않는다. 데모: [samples/stash](../../samples/stash/README.md) "보관함" 이
[samples/packages/inventory](../../samples/packages/inventory) 를 설치해 쓴다.

## 6. 알려진 문제 · 열린 검증

```text
- 심볼릭 링크 거절 시험은 이 개발 PC 에서 링크를 만들 권한이 없어 건너뛰었다 ("A required privilege is not held by the client").
  훑기의 링크 거절 코드는 있지만 이 PC 에서 실행 확인은 없다 (Linux CI · 개발자 모드에서 돈다)
- path 소스의 digest 는 디스크의 바이트다 — 줄 끝을 바꿔 꺼낸 폴더 (autocrlf) 는 다른 digest (ADR-0072 위험). 저장소는
  .gitattributes eol=lf 라 샘플은 안전하다
- 열 때마다 설치 팩 전체를 SHA-256 으로 훑는다 (아래 7장 — 데모 크기에서 수십 ms)
- 네트워크로 접속하는 클라이언트는 패키지를 받지 않는다 — 서버가 설치한 팩을 쓰는 게임에 원격으로 들어가려면 같은 프로젝트
  (sbx install) 가 있어야 한다 (v0.7)
- 한 번씩 재현되지 않은 실패 둘: det_eco_lifecycle 이 1.2 초 만에 실패한 실행 하나 (보통 16 초 — 출력 없음, 다시 세 번 · 이후
  모든 실행 통과), SandboxTests 를 직접 돌린 실행 하나에서 케이스 하나 (어느 것인지 남기지 못함 — 이후 통과)
- render_tests_warp · chcp 65001 · v0.1 의 열린 항목 (실기 QA · 50k 판정 · CI 결과) 은 v0.3 노트 6장 그대로
- samples/stash 의 기대 해시는 MSVC 키만 기록했다 — 다른 툴체인에서는 해시를 보지 않는다 (서버 = 로컬 비교는 한다)
- 네트워크는 LAN · 신뢰 환경 전용 (R6 — 암호화 없음)
```
