# v0.5 — Creator Alpha

> **문서 상태:** 설계 초안 v0.1 | **기준일:** 2026-10-13 | **대상:** Sandbox C++23 기반 게임 제작·배포 플랫폼
> **범례:** [현행] GitHub `blackvrice/Sandbox`에서 확인한 구현, [신규] 새로 설계·구현할 기능, [결정 필요] 제품 정책 확정 전

## 1. 목표와 범위
**핵심 목표:** 첫 외부 제작자 사용 가능 릴리스.

제작 → 확장 패키지 설치 → 테스트 → 배포·공유 → 타인 실행의 전체 흐름을 완성한다.

**버전 정책:** 상용 Marketplace/공식 Cloud 없이도 ZIP/파일 또는 Git 기반 GamePackage 공유가 가능해야 한다.

## 2. 진입 조건
이전 버전의 모든 필수 완료 기준 충족 및 릴리스 후보 통합 테스트

## 3. 구현 요구사항

1. Editor 온보딩/템플릿 3종(미니게임/RTS/생존 등)

2. GamePackage 빌드·패키징·검증·설치 UX, 예제 및 튜토리얼

3. SandboxScript 샘플/디버깅/오류 메시지 개선

4. 버그 리포트·충돌 로그·에러 대시보드(민감정보 제거)

5. 샘플 프로젝트 및 공개 Alpha 배포 채널

6. 개발자 외부 테스트 피드백과 릴리스 차단 기준 정리

## 4. 아키텍처/데이터 영향

- 모듈 사이 역할·권한·데이터 소유자를 문서화하며, 기존 서버 권위 ECS·결정론·비동기 경계 원칙을 우선한다.

- Manifest·Script SDK·Network·Save의 변경사항은 호환 버전/Schema Migration 계약으로 관리한다.

## 5. 자동화 완료 기준

- [ ] 제작자 A가 외부 Feature 설치·게임 빌드·공유

- [ ] 사용자 B가 별도 환경에서 실행, 호환성 문제 진단 가능

- [ ] 코드 없는 미니게임과 Script 기반 미니게임 각 1개 E2E 통과

- [ ] 치명 크래시·데이터 손상·VM 탈출 결함 미해결 시 배포 중지

## 6. 데모 및 검증 시나리오

최소 1개의 재현 가능한 데모 프로젝트와 CI/CTest 실행 명령, 실패 시 기대 오류를 릴리스 문서에 포함한다. Creator Alpha 기능을 외부 사용자가 처음부터 재현할 수 있어야 한다.

## 7. 위험·보류 항목

- 첫 사용자 온보딩 실패율/빌드 실패 UX

- 크로스 플랫폼 미완성은 명시 지원 매트릭스로 처리

## 8. 관련 상세 명세

- `architecture/03_EDITOR_AND_NOCODE.md`

- `architecture/02_GAME_PACKAGE_FORMAT.md`

## 9. Definition of Done

- 핵심 E2E 성공, 크래시/취약점/데이터 손상 문제의 출시 차단 기준 통과.

- 새 API 및 사용자 흐름 문서화, 마이그레이션/롤백 검증 완료.

- 미구현 항목을 릴리스 노트에 명시하고 다음 버전으로 재할당.
