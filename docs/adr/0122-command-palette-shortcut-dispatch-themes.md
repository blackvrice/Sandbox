# ADR-0122. 명령 팔레트 · 단축키 표 · 명령 표의 단축키 실행 · 테마 셋 (어두움 · 밝음 · 고대비)

- 상태: **Accepted** · 날짜: 2026-11-10
- 관련: [ADR-0108](0108-editor-services-target-command-table.md) (CommandService — 명령 표 하나), [ADR-0118](0118-studio-shell-dockspace-design-system.md) (셸 · 디자인 토큰),
  [29-STUDIO-UI](../29-STUDIO-UI.md) 3 · 4장, [25-STUDIO-ARCHITECTURE](../25-STUDIO-ARCHITECTURE.md) 4장, task-registry ST-06-2

## 맥락

CommandService 는 v0.8 ST-06-1 부터 명령 표 (id · 제목 · 단축키 · 곳 · when · run) 와 찾기 · 충돌 진단을 가졌지만, 단축키는 메뉴에 **보이기만**
했다 (Ctrl+N · Ctrl+O · Ctrl+B 를 눌러도 아무 일도 없었다). 앱의 다른 키 (Ctrl+S · Ctrl+Z · 1 ~ 5 · Space · F1 ~ F4 …) 는 행동 표
(ActionMap — input.json, 게임 입력과 같은 길) 가 듣는다. 테마는 어두움 하나였다 (29 3장 — 밝음 · 고대비 [계획]).

## 결정

```text
1. 명령 팔레트 (editor/ui/CommandPalette): Ctrl+Shift+P · 도움말 메뉴. 이름 · id 찾기 (CommandService::search), ↑ ↓ · Enter · Esc,
   할 수 없는 명령은 흐리게, 줄마다 키. 포커스를 잃으면 닫는다. 단축키 표 창: 키 · 이름 · id + 충돌 목록
2. 키는 두 주인을 그대로 둔다:
   - 명령 표의 shortcut — ImGui 프레임 안에서 ImGui::Shortcut (RouteGlobal) 으로 실행, 글자 칸에 쓰는 중이면 쉰다 (io.WantTextInput).
     지금: Ctrl+N · Ctrl+O · Ctrl+B · Ctrl+Shift+P · F5 (플레이) · Shift+F5 (멈춤)
   - 행동 표 (ActionMap) 의 키 — 명령은 keyHint 로 **보이기만** (팔레트 · 단축키 표). runShortcut · 충돌 진단에 들지 않는다
   한 키를 두 곳이 듣지 않는다. 행동 표를 명령 표로 옮기기 (사용자 키 다시 매기기) 는 [계획] — 게임 입력과 편집 입력을 나눌 때
3. 셸의 일 (저장 · 플레이 · 멈춤 · 일시정지 · 한 틱 · 되돌리기 · 툴 · 격자 · 맞춤 · 배치 · 테마 · 창) 을 명령으로 등록. 명령은 ShellActions 를 채우고
   다음 셸 단계에서 툴바 · 메뉴와 **같은 길** (applyShellActions) 로 한다 — 일을 두 번 짜지 않는다
4. 테마: Dark (기본) · Light · HighContrast — 같은 토큰 이름, 색만 다르다. 대비는 WCAG 공식으로 계산해 시험이 지킨다 (본문 7:1 · 보조 · 상태 ·
   강조 위 글자 4.5:1 이상, 고대비는 보조 · 강조도 7:1). 고대비는 테두리를 굵게 (색만으로 구분하지 않는다). 보기 메뉴 · 명령, studio.json "theme"
```

## 근거

```text
- 표 하나: 메뉴 · 팔레트 · 단축키 표 · 키가 같은 명령을 보면 이름 · 끔 조건이 어긋나지 않는다 (ST-06-1 의 목적)
- 두 주인: 행동 표의 키는 게임 입력과 같은 상태 기계 (누름 · 뗌 · 반복 · 텍스트 입력 중 끔) 를 지난다. 한꺼번에 옮기면 게임 키 · 편집 키 · 시험이 다
  흔들린다 — 이번에는 보이기만 맞춘다
- ImGui::Shortcut: 같은 프레임의 다른 위젯 (입력 칸) 과 키 소유를 나눈다 (라우팅)
- 계산된 대비: 색을 눈으로 고르면 밝은 테마의 강조 노랑 (#F5B83D) 이 흰 바닥에서 1.8:1 이 된다 — 밝음은 강조를 #8A5A00 으로
```

## 결과

- 얻는 것: 팔레트 · 단축키 표 · 실제 단축키 (Ctrl+N · O · B · Shift+P · F5 · Shift+F5), 명령 30 여 개, 세 테마 · 저장, 시험 (키 글자 해석 · 대비 ·
  헤드리스 앱의 팔레트 · Ctrl+Shift+P · 명령 → 툴 · 테마).
- 포기하는 것: 사용자 키 다시 매기기 (명령 표 키 덮기 — [계획]), 별칭 · 최근 쓴 명령 순서 [계획], 편집기 글꼴 · 크기 설정 [계획].
- 위험: 행동 표의 키를 바꾸면 keyHint 가 어긋난다 — 기본 input.json 기준으로 적었다 (사용자 바인딩을 읽어 보이기는 [계획]).

## 대안

| 대안 | 기각 사유 |
|------|-----------|
| 모든 키를 명령 표로 옮긴다 | 게임 입력 상태 기계 · 기존 시험이 같이 흔들린다 — 다음 단계 |
| 키 소유를 ImGui::IsKeyChordPressed 로 | 입력 칸 · 다른 창과 라우팅을 나누지 못한다 |
| 테마를 사용자 색 파일로 | 대비를 지킬 수 없다 — 셋을 고정하고 시험 |

## 재검토 조건

사용자 키 다시 매기기 · 플러그인 명령 (v0.21), 편집기 글꼴 설정, 행동 표 · 명령 표 합치기.
