# ADR-0061. 스크립트 컴포넌트의 세이브 마이그레이션 — 함수 없이 자동: 뺀 필드는 버리고 (경고), 더한 필드는 기본값, 그 밖의 변환은 엄격한 읽기가 거절

- 상태: **Accepted** · 날짜: 2026-10-26
- 관련: [ADR-0059](0059-script-components-schema-dynamic-pool-name-order-catalog.md) 7 (마이그레이션은 M3-T4), [09-SERIALIZATION](../09-SERIALIZATION.md)
  6장 (엔진 컴포넌트의 JSON 단계 마이그레이션), [ADR-0013](0013-save-folder-swap-and-load-hash.md) (로드 해시), [19-SANDBOXSCRIPT](../19-SANDBOXSCRIPT.md)
  15장, [18-PLATFORM](../18-PLATFORM.md) 6.2 (v0.3 M3-T4)

## 맥락

엔진 컴포넌트는 version 을 올리면 C++ 마이그레이션 함수 (MigrationRegistry — 09 6장) 를 등록해야 세이브를 연다. 스크립트 컴포넌트는
게임 제작자가 스크립트로 정의하고 자주 바꾼다. 스크립트에는 전역 실행이 없고 (ADR-0056 4) 세이브를 여는 쪽은 서버 · 도구라, 스크립트가
마이그레이션 함수를 줄 자리가 아직 없다. 정할 것: 저장 version 과 스키마 version 이 다를 때 · 같은데 모양이 다를 때 무엇을 하나.

## 결정

```text
1. 저장 version < 스키마 version → 자동으로 옮긴다 (persist::migrateScriptComponent):
     스키마에 없는 필드 = 버린다 — 로드 경고 한 줄 ("스크립트 컴포넌트 'id' 를 v1 → v2 로 옮겼다 (개체 N) — 버린 필드: …")
     저장 값에 없는 필드 = 기본값 (읽기가 그대로 둔다)
     i32 · enum 이 된 필드의 정수인 실수 (3.0) = 정수로
   그 뒤의 읽기는 지금과 같이 엄격하다: 종류가 맞지 않는 값 · 새 범위 밖의 값은 "'id' v1 → v2 마이그레이션 뒤 읽지 못했다" 로
   로드 실패 (필드 경로를 짚는다). 조용히 값을 바꾸거나 자르지 않는다
2. 저장 version > 스키마 version → VersionMismatch ("스크립트를 되돌렸나")
3. 같은 version 인데
     저장 값에 스키마에 없는 필드 → 로드 실패, "필드를 빼거나 이름을 바꿨으면 version 을 올린다"
     스키마의 필드가 저장 값에 없다 (더하기만) → 기본값으로 채우고 옮긴 것으로 친다 (경고 "… 모양을 바꾸면 version 을 올린다")
4. 옮긴 것이 하나라도 있으면 그 로드의 해시 비교를 건너뛴다 (지금 규칙 — "마이그레이션이 적용됨"). 옮긴 월드를 다시 저장하면
   새 version 으로 쓰고, 다음 로드는 해시까지 맞는다
5. 스크립트가 마이그레이션 함수를 주는 길 (onMigrate · 필드 이름 바꾸기 표) 은 [검토 v0.4] — 패키지 버전 · 의존성과 함께
```

## 근거

```text
- 더하기 · 빼기가 스키마 변경의 대부분이다. 이 둘을 자동으로 하면 제작자가 C++ 없이 게임을 고친다
- 뺀 필드를 버리는 것은 version 을 올린 뒤에만 — version 이 "모양을 바꿨다" 는 제작자의 표시다. 같은 version 에서 필드가 사라지면 실수
  (오타 · 이름 바꾸기) 일 수 있어 멈춘다
- 종류 · 범위 변환을 조용히 하지 않는다: 세이브의 값이 바뀌면 게임 결과가 바뀐다 (04). 정수로 바꾼 필드의 3.0 처럼 값이 그대로인 것만 옮긴다
- 같은 version 의 "더하기만" 은 거절하면 개발 중 매번 version 을 올려야 해 번거롭고, 값을 잃지 않는다. 대신 해시 비교를 건너뛰고 경고한다
  (거절하면 D2 해시 불일치로 실패했다 — 바이트가 달라진다)
```

## 결과

- 얻는 것: 스크립트 스키마를 바꿔도 세이브가 열린다 (더하기 · 빼기 · 정수화), 값이 바뀌는 변환은 오류로 드러난다.
- 포기하는 것: 이름 바꾸기 · 단위 바꾸기 같은 계산 변환 (v0.4 검토), 뺀 필드의 값 (버린다 — 경고만).
- 위험: 실수로 version 을 올리고 필드 이름을 바꾸면 옛 값이 버려진다 — 완화: 로드 경고에 버린 필드 이름이 나온다 (서버 로그 · 에디터).

## 대안

| 대안                                       | 기각 사유                                                                   |
|--------------------------------------------|-----------------------------------------------------------------------------|
| 엔진처럼 마이그레이션 함수를 반드시 요구    | 스크립트에 그 자리가 없다 (전역 실행 없음), 제작자가 C++ 를 쓸 수 없다       |
| 모든 변환을 최선으로 (자르기 · 바꾸기)      | 세이브 값이 조용히 바뀐다 (04)                                              |
| 옮길 수 없으면 그 컴포넌트를 Opaque 로     | 월드가 열리지만 시스템이 그 값을 못 본다 — 게임이 조용히 달라진다            |
| 같은 version 의 모양 변화를 모두 거절      | 개발 중 마찰, 더하기만은 값을 잃지 않는다                                    |

## 재검토 조건

이름 바꾸기 · 단위 변환이 데모 · 사용자에게서 자주 필요하면 (스크립트 onMigrate · 필드 별칭), v0.4 패키지가 의존 팩의 스키마 버전 범위를
요구하면.
