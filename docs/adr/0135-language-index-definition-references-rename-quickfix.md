# ADR-0135. 언어 서비스 색인 — 검사기 기호로 정의 · 참조, 이름 바꾸기는 바꾼 글을 다시 검사해 부딪힘을 거절, 빠른 수정, 검사 결과 기억

- 상태: **Accepted** · 날짜: 2026-11-12
- 관련: [ADR-0091](0091-script-language-service-in-sandboxscript.md) (언어 서비스는 script/lang), [ADR-0129](0129-language-service-typed-completion-hover.md)
  (완성 · hover), [27-SCRIPT-IDE](../27-SCRIPT-IDE.md) 2 · 4 · 7 · 8장, task-registry ST-06-8 (조각 1)

## 맥락

ST-06-8 은 정의로 · 참조 · 이름 바꾸기 · 빠른 수정 · 증분 분석이다. 검사기는 이름 마디마다 가리키는 기호 (NodeSema::refIndex) 를 적고,
가져온 이름은 내보낸 쪽의 기호로 묶는다 (파일 사이 참조가 같은 기호다). 그러나 import { X } 의 X 마디와 타입 자리의 이름 (TypeName) 에는 기호를
적지 않고, 선언 마디의 자리는 키워드 · export 앞일 수 있다. 언어 서비스의 질의 (완성 · hover · 진단 · 색인) 는 같은 글로 검사기를 여러 번 부른다.

## 결정

```text
1. script/lang/LanguageIndex — 별도 색인 자료 없이 검사 결과에서 바로: 기호의 자리 = ① 이름 마디 (ref Symbol) ② import { X } 의 X (검사기의
   resolveImports 와 같은 규칙으로 대상 모듈을 풀어 그 export) ③ 타입 자리 이름 (그 타입 번호를 가진 Type · Enum 기호) ④ 선언 = 선언 마디 자리부터
   그 이름 낱말. 색인 대상 = 지역 · 매개변수 · 모듈 상수 · 함수 · 컴포넌트 · enum · interface · type (SDK · 내장 · 필드 · enum 멤버 · Host 멤버는
   아니다 — 필드 이름 바꾸기는 [계획])
2. findDefinition · findReferences (선언 먼저, 그다음 파일 · 자리 차례)
3. renameSymbol: 그 기호의 모든 자리 중 글자가 그 이름인 곳만 (as 로 붙인 지역 이름은 그대로). 거절 — 새 이름이 렉서로 이름 한 낱말이 아니면
   (예약어 · 숫자 시작 · 공백 · 비 ASCII), SDK · 내장, 의존 팩 ("@") 의 기호, 바꾼 글을 다시 검사해 오류 수가 늘면 (부딪힘 · 가림 — 새 진단을 이유로).
   부딪힘을 따로 계산하지 않고 검사기에 묻는다 — 범위 규칙이 하나
4. quickFixes (그 자리에 S401 없는 이름이 있을 때): "sandbox" 의 이름이면 import, 팩의 다른 파일 (의존 팩 "@팩/…") 이 내보내면 import (같은 곳의
   import 줄이 있으면 그 { } 끝에, 없으면 마지막 import 뒤 · 맨 위에 새 줄), 비슷한 이름 (편집 거리 ≤ 2 — 이 모듈의 기호 · 가져온 이름 · 전역,
   가까운 차례 셋)
5. 검사 결과 기억 (script/lang/ProgramCache): 입력 (파일 경로 · 글 · 팩 import) 의 FNV-1a 64 + 전체 비교로 최근 넷. 언어 서비스의 모든 질의 ·
   편집기 진단 (ScriptAssist) 이 함께 쓴다. 파일 단위 증분 검사 (바뀐 파일과 그 파일을 가져오는 파일만) 는 [계획] — 검사기가 모듈 사이 상태 (기호 ·
   타입 표) 를 한 Program 에 모으므로 나누는 일이 크다
```

## 근거

```text
- 검사 결과에서 바로: 별도 색인 (기호 → 자리 표) 을 유지하면 편집마다 갱신 · 무효화가 필요하다. 측정이 충분히 작다 — Release 5,000 줄 참조 14.6 ms
  (기억이 맞으면 0.27 ms), 이름 바꾸기 14.2 ms (다시 검사 포함)
- 부딪힘을 검사기로: 가림 · 같은 범위 · import 이름 · 타입 이름공간 규칙을 색인이 다시 구현하지 않는다
- 기억 넷: 편집 중인 글 · 완성의 자리표 글 · 이름 바꾸기의 시험 글이 번갈아 온다
```

## 결과

- 얻는 것: 정의 · 참조 · 이름 바꾸기 (파일 사이 · import 자리 · 타입 자리) · 빠른 수정 (import · 철자), 같은 글의 질의는 검사 한 번.
- 포기하는 것: 필드 · enum 멤버 · 컴포넌트 필드 이름 바꾸기, 문자열 안의 이름 (컴포넌트 id), 의존 팩의 이름 바꾸기 (그 팩에서), 파일 단위 증분.
- 위험: 선언 이름 찾기가 선언 마디 자리부터의 글자 찾기 (512 바이트 안) — 선언 키워드와 이름 사이가 아주 길면 못 찾는다 (그 기호는 정의 · 참조에서
  선언이 빠진다). Studio 의 F12 · Shift+F12 · F2 · 빠른 수정 UI 는 조각 2.

## 대안

| 대안 | 기각 사유 |
|------|-----------|
| 기호 → 자리 색인을 따로 유지 | 갱신 · 무효화 비용, 측정이 필요 없다고 말한다 |
| 부딪힘을 색인이 계산 | 범위 규칙을 두 곳에 |
| 검사기가 import · 타입 이름 마디에 기호를 적게 고침 | 검사기의 많은 자리를 고친다 — 색인 쪽 풀기로 같은 결과 |

## 재검토 조건

큰 팩에서 질의가 입력 멈춤 안에 못 들 때 (파일 단위 증분), 필드 이름 바꾸기, sbx lsp (v0.21 — ST-07-3 이 이 함수들을 쓴다).
