# ADR-0044. 게임 프로젝트의 세이브 폴더는 <프로젝트>/worlds, Ctrl+S 기본 이름은 시작 월드

- 상태: **Accepted** · 날짜: 2026-10-20
- 관련: [ADR-0031](0031-world-ops-generation-replay-playback.md), [ADR-0040](0040-game-project-manifest-world-is-save-folder.md),
  [ADR-0041](0041-server-opens-game-project-strict-check.md), [18-PLATFORM](../18-PLATFORM.md) 5장, [10-EDITOR](../10-EDITOR.md) 9장

## 맥락

v0.2 M1-T5 — M1 의 마지막. 프로젝트를 만들고(T4) 열 수 있지만(T2), 에디터에서 고친 월드는 작업 폴더의 `saves/quicksave` 로
저장된다 (12D 의 기본값). 편집한 맵을 게임에 넣으려면 손으로 폴더를 옮겨야 한다. 월드는 세이브 폴더 형식이므로(ADR-0040)
저장 위치와 이름만 맞추면 된다. 정할 것: 프로젝트 서버 · 싱글플레이의 세이브 폴더, Ctrl+S 의 처음 이름, --saves 와의 관계.

## 결정

```text
1. --world 가 게임 프로젝트이고 --saves 가 없으면 세이브 · 리플레이 폴더 = <프로젝트>/worlds (서버 · 싱글플레이 클라이언트
   공통 — project::projectSavesRoot). --saves 를 주면 그것이 이긴다. 서버는 로그에 "세이브 폴더: … (프로젝트의 worlds/)".
2. "월드" 창 · Ctrl+S 의 처음 이름 = 시작 월드 (entryWorld 가 "worlds/<이름>" 이고 세이브 이름 규칙에 맞을 때 — 
   project::entryWorldSaveName). 아니면 quicksave (worlds/ 밖의 시작 월드는 덮지 않는다). 싱글플레이 클라이언트만 —
   원격 접속자는 서버의 매니페스트를 모른다 (quicksave 그대로).
3. 저장은 지금처럼 임시 폴더 → 교체 (ADR-0013) — 시작 월드를 덮어도 반쯤 쓴 상태가 남지 않는다. 같은 프로젝트 콘텐츠로
   저장하므로 프로젝트 검사(경고 0)를 그대로 통과한다. 리플레이 기록도 같은 폴더에 (<이름>/start + replay.sbxr) — 검사는
   entryWorld 만 본다.
```

## 근거

```text
- 월드 = 세이브 폴더 (ADR-0040) 의 당연한 결과: 저장 · 불러오기 · 목록이 그대로 프로젝트 월드의 편집이 된다. 새 메시지 · 새
  명령 없이 기본값 두 개로 끝난다.
- Ctrl+S = 시작 월드: "고치고 저장하면 게임이 바뀐다" 가 비개발자 흐름 (03_EDITOR 3장). 다른 이름은 "월드" 창에서 고른다.
- 클라이언트만 이름을 정하는 이유: 이름은 UI 의 처음 값일 뿐 서버 규칙이 아니다. 원격 편집자가 시작 월드를 덮게 할지는 역할 ·
  권한(admin 부터 저장 — 12D)이 이미 정한다.
```

## 결과

- 얻는 것: `SandboxClient --world MyGame` → 고치고 Ctrl+S → MyGame/worlds/main 이 바뀌고 `sbx check` 통과 → 서버가 그 월드로
  시작. unit_client 시험 (기본값 표 · Ctrl+S 가 시작 월드를 덮고 검사 통과), CTest server_project_saves_root.
- 포기하는 것: 프로젝트의 worlds/ 에 리플레이 폴더가 섞인다 (분리는 Test Play 의 일 — M5).
- 위험: Ctrl+S 한 번에 시작 월드가 바뀐다 — 되돌리기는 git(프로젝트 저장소) · 다른 이름 저장. 실행 중 상태(틱 · 개체 진행)가
  시작 월드가 된다 → 편집 원본과 실행 상태의 분리는 M5-T1 Test Play (분기 세션, 원본 보호).

## 대안

| 대안                          | 기각 사유                                                                   |
|-------------------------------|-----------------------------------------------------------------------------|
| 프로젝트도 작업 폴더의 saves/ | 편집한 맵을 손으로 옮겨야 한다 — v0.2 흐름이 끊긴다                         |
| 세이브 폴더 = 프로젝트 루트   | 세이브 이름 "content" 가 팩 폴더를 덮을 수 있다                             |
| 새 명령 "프로젝트에 저장"     | 저장 · 불러오기와 같은 일을 하는 두 번째 길 — 와이어 · 권한 규칙이 늘어난다 |
| Ctrl+S 는 그대로 quicksave    | 비개발자가 "저장했는데 게임이 그대로" 를 겪는다                             |

## 재검토 조건

M5-T1 Test Play (편집 원본과 실행 상태를 나눌 때 — 시작 월드 저장은 편집 상태에서만), 리플레이를 따로 둘 때, 원격 편집자의
"게임에 저장" 권한을 따로 둘 때.
