# ADR-0136. Studio 스크립트 편집기의 색인 — F12 · Shift+F12 · F2 · Ctrl+., 파일마다 고친 글 (drafts), 편집은 입력 칸의 콜백으로, 스니펫

- 상태: **Accepted** · 날짜: 2026-11-12
- 관련: [ADR-0135](0135-language-index-definition-references-rename-quickfix.md) (색인), [ADR-0130](0130-script-editor-widget-imgui-input-assist-service.md)
  (편집기 위젯), [ADR-0131](0131-script-save-to-pack-file-line-endings.md) ([적용] / [저장]), [27-SCRIPT-IDE](../27-SCRIPT-IDE.md) 3 · 4 · 8장,
  task-registry ST-06-8 (조각 2)

## 맥락

색인 (조각 1) 을 콘텐츠 창의 스크립트 편집기에 붙인다. 정의로 가기는 다른 파일을 열고, 이름 바꾸기는 여러 파일을 고친다. 그런데 콘텐츠 창은 한
번에 한 항목만 고치고, 다른 항목을 고르면 고친 글을 버렸다 (팩 값으로 다시 불렀다). 편집기 (ImGui 입력 칸) 의 글을 바깥에서 바꾸면 입력 칸을 새로
만들어 되돌리기 기록이 사라진다.

## 결정

```text
1. 키 (편집기 위젯 — 입력 칸이 활성일 때, 키 경로 RouteFocused | RouteOverActive): F12 정의로, Shift+F12 참조, F2 이름 바꾸기, Ctrl+. 빠른 수정 →
   커서 자리의 요청 (ScriptEditorState::request). 위젯은 색인을 모른다 — 콘텐츠 창이 요청을 처리한다 (위젯 · 서비스 분리 그대로)
2. 파일마다 고친 글 (ContentPanelState::drafts — 스크립트 id → 글): 다른 스크립트 · 종류로 옮기면 지금 글을 남기고 (팩 값과 같으면 지운다), 다시 열면
   그 글. 목록에 ✎. [고친 것 버리기] 가 지운다. 진단 · 완성 · 색인의 작업 공간도 drafts 를 쓴다 (scriptWorkspace — 오버레이 · 팩 원본보다 앞) — 이름
   바꾸기로 두 파일이 함께 바뀐 상태가 오류 없이 보인다
3. 이름 바꾸기: 이 파일의 편집은 편집기의 pendingEdits (입력 칸이 활성이면 콜백 안에서 DeleteChars · InsertChars — 되돌리기에 남고, 커서는 앞 편집만큼
   민다), 다른 파일은 drafts 에 (열어 [적용 (오버레이)] · [저장 (팩 파일)] 은 사람이 — 여러 파일을 한 번에 서버 · 디스크에 쓰지 않는다). 새 이름은
   작은 창 (커서의 이름을 채워 둔다), 거절은 이유를 진단 목록에
4. 빠른 수정: 그 자리의 고침 목록 (작은 창) — 이 파일만 고치는 것만 (색인의 빠른 수정은 import · 철자 — 모두 이 파일). 편집은 pendingEdits
5. 정의로: 이 파일이면 커서, 다른 파일 (의존 팩 파일 포함) 이면 그 스크립트를 연다 (지금 글은 drafts 에). 참조: 진단 목록 칸에 "파일:줄  그 줄" —
   누르면 그 자리로
6. 스니펫 (언어 서비스): 이름 완성에 문장 처음 (그 줄에서 이름 앞이 빈칸) 일 때만 system · component · forquery 틀 (CompletionKind::Snippet ·
   insertText). 넣으면 둘째 줄부터 넣는 줄의 들여쓰기를 붙인다 (ScriptAssist::acceptCompletion)
```

## 근거

```text
- drafts: 이름 바꾸기 · 정의로 가기가 파일을 옮겨 다니는데 고친 글을 버리면 데이터 손실이다 (M6-T7 자동 저장과 같은 이유)
- 다른 파일을 drafts 로만: [적용] 은 서버의 오버레이 · 컴파일, [저장] 은 디스크 — 사람이 파일마다 확인하고 고른다 (ADR-0131 의 두 단추 그대로)
- 콜백 편집: 입력 칸의 되돌리기 (Ctrl+Z) 로 이름 바꾸기 · 빠른 수정을 되돌린다
```

## 결과

- 얻는 것: Studio 안의 정의 · 참조 · 이름 바꾸기 (여러 파일) · 빠른 수정 · 스니펫, 파일을 옮겨도 남는 고친 글.
- 포기하는 것: 여러 파일의 한 번에 적용 · 저장 (파일마다), 다른 파일 편집의 되돌리기 (drafts 는 [고친 것 버리기] 로), 마우스로 정의로 (Ctrl+클릭),
  스니펫의 자리 이동 (Tab 으로 다음 칸).
- 위험: drafts 는 창의 메모리에만 — Studio 를 끄면 사라진다 (자동 저장의 문서 복구는 DocumentService 문서만 — [계획] drafts 도). 서버 값이 바뀌어도
  drafts 는 그대로다 (다시 열면 고친 글 — 버리기로 돌아간다).

## 대안

| 대안 | 기각 사유 |
|------|-----------|
| 다른 파일도 바로 [적용] | 여러 파일을 서버에 한꺼번에 — 사람이 보지 않은 글이 월드에 |
| 다른 파일을 열 때마다 고친 글을 버림 (지금까지) | 이름 바꾸기 · 정의로에서 데이터 손실 |
| 이 파일의 편집도 글을 바로 바꿈 | 입력 칸을 새로 만들어 되돌리기 기록을 잃는다 |

## 재검토 조건

drafts 의 자동 저장 · 복구, 여러 파일 한 번에 적용 · 저장, 일반 문서 탭 편집기 (DocumentService), Ctrl+클릭.
