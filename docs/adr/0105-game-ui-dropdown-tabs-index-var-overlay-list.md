# ADR-0105. 게임 UI 고르기 — dropdown · tabs 의 값은 var 의 번호, 열린 목록은 문서들 위 (밖을 누르면 닫기), tabs 는 고른 자식만 배치 · 머리 칸만 잡기

- 상태: **Accepted** · 날짜: 2026-11-09
- 관련: [ADR-0103](0103-game-ui-input-controls-var-state-focus.md) (입력 컨트롤 — 값 · 신호 · 포커스),
  [ADR-0104](0104-game-ui-text-input-client-var-length-signal.md) (글자 칸), [20-CREATOR-ALPHA](../20-CREATOR-ALPHA.md) 2.6 (NG-06)

## 맥락

NG-06 (3) 은 Dropdown · ScrollView · Tab · 게임패드 탐색이다. 게임패드는 플랫폼 입력 (I5 — InputState.gamepads 는 [계획]) 이 먼저라
뒤로 미루고, ScrollView 는 배치에 밀기 상태를 더하는 일이라 따로 한다. 이 ADR 은 여럿 중 하나를 고르는 두 컨트롤 — dropdown (닫힌 상자
+ 열리는 목록) 과 tabs (머리 칸 + 몸통) — 를 정한다. 배치 · 그리기는 문서마다 따로 돌고 (앞 순서), 라우팅은 층 차례 (modal → menu →
hud) 이며, 나중 노드가 위다. 열린 목록은 문서의 노드가 아니다 — 다른 노드 · 문서 위에 겹친다.

## 결정

```text
1. 값 = "var:<키>" 의 번호 (0 부터, 반올림 — 모르는 값 · 범위 밖은 "고른 것 없음"; tabs 는 0 번을 보인다). 바뀌면 컨트롤이 var 에
   수로 쓰고 on.change 신호 (값 = 번호) — ADR-0103 1 · 2 와 같은 길. 같은 번호를 다시 고르면 신호 없음
2. dropdown: options (1 ~ 32 글자 — "@<키>" 는 문자열 표), 닫힌 상자 = 가장 긴 option + 여백 + 화살표 칸. 누르면 목록이 열린다
   (어느 층이든 — 포커스는 ADR-0103 4 대로 menu · modal 만). 목록 = 상자 아래 (줄 높이 = 상자 높이), 화면 아래를 넘고 위에 자리가
   있으면 위. GameUiLayer 가 모든 문서 뒤에 그리고, 라우팅에서 문서들보다 먼저 본다: 목록 위의 포인터는 목록의 것 (가리킨 줄), 누르면
   고르고 닫는다. 밖을 누르면 닫고 그 누름은 아래로 간다 — 열린 dropdown 자신을 누른 것이면 닫기만
3. tabs: labels (1 ~ 32) 와 children 이 하나씩 (U1). 머리 칸 = labels 를 안쪽 왼 위부터 차례로 (글자 + 여백), 몸통 = 머리 아래 —
   고른 자식만 배치한다 (숨긴 노드처럼 나머지는 자리 · 라우팅 · 포커스 차례에 없다). 크기는 가장 큰 자식으로 (고를 때 흔들리지 않게).
   라우팅은 머리 칸 위에서만 tabs 를 잡는다 — 몸통은 자식의 것. 포커스 고리는 머리 칸들
4. 키 (포커스가 있을 때 — ADR-0103 5 에 더함): 왼 · 오른 = 한 칸 고르기 (dropdown 은 닫힌 채, tabs 는 머리 칸). dropdown 은 Enter ·
   Space = 열기, 열린 동안 위 · 아래 = 가리킨 줄, Enter · Space = 고르고 닫기, Esc = 닫기 (포커스는 남는다). 포커스가 다른 컨트롤로
   가면 목록을 닫는다
5. 게임패드 탐색은 플랫폼 게임패드 입력 (I5) 뒤 [계획] — UiKey 가 이미 방향 · 누르기 · 놓기라 패드는 그 키로 옮기기만 하면 된다.
   ScrollView 는 NG-06 (3b) [계획]
```

## 근거

```text
- 번호 하나: slider 와 같은 수 var — 스크립트 (ctx.uiVar) 와 서버 신호 (i32) 가 그대로 읽는다. 문자열 값 (option 이름) 은 번역되면
  바뀐다 — 번호는 로케일과 무관
- 목록을 문서 밖 (층) 에: 목록이 부모 panel 의 clip 에 잘리지 않고, 다른 문서 위에 겹친다. 하나만 열린다 (상태 = 노드 하나)
- 밖을 누르면 닫고 그 누름을 아래로: 목록을 닫으려고 한 번 더 누르게 하지 않는다 (흔한 데스크톱 동작). 자신은 닫기만 (토글)
- tabs 가 머리 칸만 잡기: 몸통의 버튼 · 컨트롤이 tabs 에 가려지지 않는다
```

## 결과

- 얻는 것: 설정 메뉴의 고르기 (해상도 · 난이도 · 언어 같은), 탭으로 나눈 메뉴, 키보드만으로 조작.
- 포기하는 것: 목록 안 밀기 (option 이 많아 화면을 넘으면 넘친다 — 32 개 상한, ScrollView 뒤), 타자로 option 찾기, 여러 개 고르기.
- 위험: hud 의 열린 목록은 포커스 없이 열려 Esc 로 닫지 못한다 (밖 · 자신을 눌러 닫는다).

## 대안

| 대안                                   | 기각 사유                                                                   |
|----------------------------------------|-----------------------------------------------------------------------------|
| 값 = option 글자                       | 번역 · 표 바꾸기에 흔들린다, 신호 (i32) 로 못 보낸다                          |
| 목록을 문서의 노드로 (자식)             | 부모 clip · 쌓기에 묶이고, 뒤의 문서 아래로 그려진다                          |
| 밖을 누르면 닫기만 (누름은 버린다)       | 다른 버튼을 누르려면 두 번 — 게임 중 hud 에서 거슬린다                       |
| tabs 의 모든 자식을 배치하고 숨김 표시   | 숨은 자식의 컨트롤이 포커스 차례 · 라우팅에 남는다                            |

## 재검토 조건

ScrollView (목록 밀기), 게임패드 입력 (I5), 접근성 점검 (v1.0 — 화면 읽기의 "목록 열림" 알림).
