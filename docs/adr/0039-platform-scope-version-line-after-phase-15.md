# ADR-0039. 제품 범위를 게임 제작 · 배포 플랫폼으로 넓힌다 — Phase 0~15 = v0.1, 이후는 버전 · 마일스톤 · 태스크

- 상태: **Accepted** · 날짜: 2026-10-19
- 관련: [00-OVERVIEW](../00-OVERVIEW.md) 1 · 7장, [03-SIMULATION](../03-SIMULATION.md) 6.4, [16-ROADMAP](../16-ROADMAP.md) 2 · 6장,
  [18-PLATFORM](../18-PLATFORM.md), [플랫폼 설계 초안](../platform/START_HERE.md) (2026-10-13), [ADR-0011](0011-explicit-component-registration.md),
  [ADR-0024](0024-network-foundation-enet-serverhost-two-halves.md)

## 맥락

Phase 0~15 로 "장르에 묶이지 않는 시뮬레이션 메이커"(엔진 · 멀티플레이 에디터 · 3 백엔드 · 50k 최적화)를 만들었다. 사용자가
제품 방향을 넓혔다 (docs/platform/ 초안): Roblox 처럼 비개발자가 게임을 만들고 플레이하고, Unity 처럼 Component · System 을
조합하고, GitHub · npm 처럼 프로젝트 · 패키지를 공유하고, 자체 호스팅 · 무료 세션 · 유료 상시 서버 · 판매 · 구독까지 —
v0.1~v1.0 의 10 개 버전. 이 방향은 지금의 규범 문서와 부딪힌다:

```text
1. 00 1장 "시뮬레이션 메이커" · 7장 비목표 "초기 스크립팅 언어(Lua/WASM) — Rule op + FSM 데이터로 시작"
2. 16 6장 범위 밖: 스크립팅 언어 · 공개 인터넷 서버 운영(암호화 · 계정) · 워크샵/월드 공유 플랫폼
3. 03 6.4: Rule op 로 안 되는 요구가 3 건 쌓이면 Rule Graph / Lua / WASM 을 검토 — 언어 후보가 다르다 (초안: TypeScript 부분집합)
4. ADR-0011 컴포넌트는 C++ 에서 명시 등록 — 초안 v0.3 은 스키마로 등록하는 사용자 컴포넌트를 요구한다
5. ADR-0024 ENet 평문, LAN · 신뢰 환경 한정 (위험 R6) — 초안 v0.7 은 공개 방 · 무료 세션 서버
6. 진행 단위가 "Phase N" 인데 초안은 "v0.N" — 둘의 대응이 없다
```

## 결정

```text
1. 제품 = Sandbox Platform: Engine(지금의 시뮬레이션 메이커) + Game Creator + SandboxScript + Package Manager + Hub
   + Cloud + Marketplace. 시뮬레이션 메이커는 없어지지 않고 Engine · Editor 층으로 그대로 남는다.
2. 버전 줄: Phase 0~15 = v0.1 Engine Foundation (기준선). 남은 v0.1 검증(Phase 6~8 · 13 실기 QA, Phase 14 macOS, Phase 15
   사용자 PC 50k 측정, CI 결과)은 v0.1 의 열린 항목으로 이어 간다 — v0.2 개발을 막지 않는다 (서로 다른 코드).
   v0.2 부터 작업 단위는 "v0.N Mk-Tn" (버전 · 마일스톤 · 태스크, 예: v0.2 M1-T1). Phase 번호는 16 으로 잇지 않는다.
3. 범위에 들어오는 것과 그 시점 (구체 설계는 해당 버전에 들어갈 때 ADR 로):
   - 스크립팅: v0.3, TypeScript 문법 부분집합 → Typed IR → 바이트코드 → C++ VM. Lua · WASM 은 후보에서 뺀다.
     v0.2 까지는 03 6.4 의 원칙(새 표현력은 Native op · 데이터로) 그대로 — v0.2 no-code 기능은 Native Feature + 데이터.
   - 사용자 컴포넌트 스키마 · 동적 풀: v0.3 (ADR-0011 은 내장 컴포넌트에 계속 유효, 동적 등록은 새 ADR 이 더한다).
   - 패키지 · 공유: v0.4 로컬/Git 패키지, v0.5 파일 공유, v0.6 Hub.
   - 공개 인터넷: v0.7 진입 전 보안 전송 ADR 필수 (R6 · ADR-0024 의 조건 그대로). 결제 · 호스팅: v0.8, 실제 사용자 노출은
     보안 · 운영 조건을 통과한 뒤.
4. 바뀌지 않는 것: 서버 권위, 30 TPS 고정 틱, 결정론 · WorldHash · Replay (04 가 여전히 최우선), SimCommand · ECB ·
   SystemScheduler 규칙, Sparse-Set ECS 와 stableId, 경계(Server 는 그래픽 · 창 없음, Render 는 ECS 모름), DX12 · Vulkan ·
   Metal, 클라이언트 게임플레이 예측 없음.
5. 문서: 18-PLATFORM = 플랫폼 계획 (현황 표 · 버전 의존 · 마일스톤 · 열린 결정 · 진행 상태). docs/platform/ = 초안 원본 (동결,
   비규범 — 현행 구현 서술은 2026-10-13 기준이라 18 이 고친다). 16-ROADMAP 은 Phase 0~15 이력 + 18 로 가는 입구.
6. 버전 번호는 축마다 따로: 제품 버전(CMake project VERSION — 버전이 끝날 때 올린다, v0.2 완료 = 0.2.0), kSimVersion,
   세이브 worldVersion · schemaVersion, 프로토콜 버전, 매니페스트 schemaVersion. 하나가 다른 것을 끌고 가지 않는다.
7. 진행 규칙 (16 1장을 그대로 잇는다): 태스크마다 빌드 · 전체 CTest 통과 커밋, 버전마다 자동 검증 가능한 완료 기준,
   버전이 끝나면 요구사항마다 done / deferred / removed 를 18 에 남긴다. 미래 버전의 기능을 미리 만들지 않는다.
```

## 근거

```text
- 플랫폼 기능은 모두 지금 엔진 위에 선다 (게임 = 콘텐츠 팩 + 월드 + 규칙, 실행 = SandboxServer, 공유 = 같은 형식의 파일).
  엔진을 다시 만들거나 갈라 놓을 이유가 없다 — 범위만 넓히고 기준선을 v0.1 로 고정한다.
- Phase 번호를 16, 17 로 이으면 초안의 v0.N 과 이중 번호가 된다. 버전이 제품 단위(출시 · 호환)라 그것을 기준으로 한다.
- 스크립트 언어: 초안이 TypeScript 를 정했고 (편집기 · 타입 도구 생태계), 실행은 자체 VM 이라 게임 실행 파일에 JS 런타임이
  없다. Lua · WASM 을 같이 열어 두면 Host API 가 둘로 갈린다.
- 공개 네트워크 · 결제의 조건(R6)은 위험이 그대로라 완화하지 않는다 — 시점만 정한다.
```

## 결과

- 얻는 것: 한 줄의 버전 계획, 기존 규범과의 충돌 6 건의 처리 방법, 남은 Phase 검증과 새 개발의 분리.
- 포기하는 것: "스크립팅 없음"이라는 단순함 (v0.3 부터 VM · SDK · 바이트코드 검증의 유지비), Lua · WASM 생태계.
- 위험: 범위 폭발 (R1 — 1 인 개발에 10 버전, v0.6 이후는 웹 서비스 · DB · 결제 대행 같은 이 저장소 밖의 운영이 필요 →
  D-06 에서 저장소 경계를 정한다). 완화: 버전마다 동작하는 세로 조각 + 자동 검증, 미래 기능 선구현 금지.

## 대안

| 대안                                         | 기각 사유                                                                       |
|----------------------------------------------|---------------------------------------------------------------------------------|
| 플랫폼을 새 저장소로                         | 엔진 · 에디터 · 서버를 그대로 쓴다 — 갈라 놓으면 경계 검사 · 결정론 하네스가 둘 |
| Phase 16, 17 … 로 계속                       | 초안의 v0.N 과 이중 번호. 출시 단위(버전)와 작업 단위가 섞인다                  |
| 03 6.4 대로 Lua · WASM 을 후보로 유지         | Host API · SDK 가 언어마다 갈린다. 초안이 TypeScript 를 정했다                  |
| 남은 Phase 검증이 끝날 때까지 v0.2 를 미룸   | 검증은 사용자 기기 · CI 를 기다리는 일이고 v0.2 코드와 겹치지 않는다            |

## 재검토 조건

v0.2~v0.5 중 한 버전이 계획의 두 배를 넘게 걸리면 (범위를 다시 자른다), 서비스 영역(v0.6+)을 이 저장소에 둘지 정할 때 (D-06),
TypeScript 부분집합이 v0.3 의 요구(결정론 · 예산 · 타입)를 맞추지 못하면.
