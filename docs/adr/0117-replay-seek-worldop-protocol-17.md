# ADR-0117. 리플레이 탐색 — WorldOp Seek (프로토콜 17), 뒤로 = 시작 세이브에서 다시 (체크포인트 캐시 없음 — 측정 뒤), 타임라인

- 상태: **Accepted** · 날짜: 2026-11-10
- 관련: [ADR-0031](0031-world-ops-generation-replay-playback.md) (WorldOp · 재생), [ADR-0116](0116-replay-viewer-client-replay-option.md) (--replay),
  [20-CREATOR-ALPHA](../20-CREATOR-ALPHA.md) 4장 (seek · 체크포인트는 M5-T2 에서 측정 뒤 결정), [08-NETWORK](../08-NETWORK.md) 4 · 5장,
  [14-PERFORMANCE](../14-PERFORMANCE.md) 7.18, task-registry M5-T2

## 맥락

재생은 멈춤 · 한 call 씩 · 속도 (×0.25 ~ ×8 — 실행 제어 명령) 가 있었고 원하는 자리로 가는 길이 없었다. 재생은 결정적이라 시작 세이브에서
같은 명령을 다시 넣으면 같은 자리다 (04 D3). 20 4장은 뒤로 가기를 "처음 세이브에서 다시" 로 두고 체크포인트 캐시는 측정 뒤 정하기로 했다.

## 결정

```text
1. WorldOp Seek (op 10) + WorldOpRequest 끝 target varint (call) — 프로토콜 17 (모든 WorldOp 에 target, Seek 밖에서는 0). 권한은 다른 WorldOp
   처럼 admin 부터. 이름이 비지 않으면 재생 중인 리플레이와 같아야 한다
2. target ≥ 지금 call: 그대로 빠르게. target < 지금: 시작 세이브를 다시 열어 새 플레이어로 월드를 바꾸고 (WorldChanged Replay — 모두 새
   epoch) 처음부터. target 은 전체 call 로 자른다 (끝 = 재생 끝 결과)
3. 빠르게 돌리기는 Sim 단계마다 20 ms 예산 (서버 · 접속 · 복제가 멈추지 않는다). 해시 비교는 그대로 (탐색도 기록을 확인한다)
4. 닿으면 멈춘 채 (paused) 보낸 사람에게 WorldOpResult{Seek, "call N · tick T (걸린 ms)"} — 이어 보기는 실행 제어 (재생)
5. 체크포인트 캐시 없음 (지금): 뒤로 탐색 = 그 call 까지 다시 재생. 측정 (14 7.18, Release · ecosystem_small): 1 분 기록 (1800 call) 의 가운데로
   0.13 초, 10 분 기록 (18000 call) 의 가운데로 3.1 초. v0.8 의 기록 (테스트 · 버그 보고 — 수 분) 에는 두지 않는다. 10 분 넘는 기록은 이미
   재검토 기준 (3 초) 을 넘으므로 N call 마다 메모리 세이브 캐시가 다음 단계 [계획 — M5-T3 기록 뒤, 재검토 조건]
6. 화면: "월드" 창의 재생 타임라인 (끌어서 놓으면 탐색), 시험 · 측정: SandboxClient --replay-seek <call> (끝 앞 → 그 call → 끝)
```

## 근거

```text
- WorldOp 에 얹기: 재생 상태 · 권한 · 결과 길이 이미 WorldOp — 실행 제어 명령 (core 의 CommandPayload) 에 넣으면 시뮬레이션 명령 형식 ·
  리플레이 기록 · kSimVersion 에 닿는다
- 다시 재생 (캐시 없이): 정확성은 결정론이 보장하고 (같은 해시 — 시험), 메모리 · 코드가 들지 않는다. 캐시는 숫자가 필요를 보일 때
- 예산 나누기: 긴 탐색 중에도 다른 접속의 하트비트 · 통계가 산다
```

## 결과

- 얻는 것: 타임라인으로 원하는 자리 (20 M5-T2 완료 칸 "뒤로 가기가 같은 자리" — test_world_ops · client_replay), 탐색 시간 로그.
- 포기하는 것: 긴 기록의 빠른 뒤로 가기 (캐시), 탐색 중 진행 막대 (지금은 끝에 결과 하나), 틱 단위 타임라인 (call 단위 — 일시정지 편집 단계도
  call 이다).
- 위험: 옛 클라이언트 (프로토콜 16) 는 접속하지 못한다 (버전 검사 — 의도된 것). 큰 월드의 뒤로 탐색은 세이브 열기만큼 더 든다 (50k 개체 ≈
  1 초 — 14 7.17 의 로드).

## 대안

| 대안                                         | 기각 사유                                                                |
|----------------------------------------------|--------------------------------------------------------------------------|
| 실행 제어 명령 SeekReplay (core 명령)          | 시뮬레이션 명령 · 리플레이 기록 형식에 닿는다 — 재생 제어는 서버 몫        |
| N call 마다 체크포인트 세이브 (지금)           | 측정이 필요를 보이지 않았다 (20 4장 — 측정 뒤 결정)                       |
| 탐색을 한 Sim 단계에 끝까지                    | 긴 기록이면 서버가 수 초 멈춘다 (하트비트 · 다른 접속)                     |

## 재검토 조건

뒤로 탐색이 Release 에서 3 초를 넘는 기록 — 측정상 10 분 기록이 이미 3.1 초 (14 7.18) — 을 사용자가 쓰게 되면 (--record 로 긴 테스트 ·
버그 보고 — M5-T3 뒤) 체크포인트 캐시, 원격 관전 (v0.7 계획) 의 지연 탐색.
