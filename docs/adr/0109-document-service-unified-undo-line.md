# ADR-0109. DocumentService (바이트 편집 · 저장 전 검사 · 바깥 변경이면 덮어쓰지 않음) · 하나의 되돌리기 줄 (참여자가 내용을, 서비스가 차례를)

- 상태: **Accepted** · 날짜: 2026-11-09
- 관련: [ADR-0089](0089-studio-editor-services-layer-imgui-first.md) 2 · 3, [ADR-0108](0108-editor-services-target-command-table.md),
  [ADR-0029](0029-inspector-server-values-undo-entries.md) (월드 편집의 Undo), [25-STUDIO-ARCHITECTURE](../25-STUDIO-ARCHITECTURE.md) 3장,
  [10-EDITOR](../10-EDITOR.md) 12D, task-registry ST-06-1

## 맥락

ADR-0089 2 는 파일 편집 (팩 JSON · 스크립트 · UI 문서 · 에셋 메타) 을 DocumentService 로만 하기로 했다 — 원자적 저장 · 저장 전 검사 · 바깥 변경
감지 · 되돌리기. 25 3장은 "Undo 는 둘 (월드 명령 · 파일 문서) 을 한 기록 줄로 — 사용자에게 Ctrl+Z 가 둘이면 안 된다" 고 한다. 월드 편집의
되돌리기 (editor/Undo — 받아들여진 명령 · 역명령 · IdRemap) 는 결과를 기다리는 비동기 흐름이고 render 를 아는 SandboxEditor 안에 있다.

## 결정

```text
1. UndoService = 차례만: 줄의 칸 {종류 (World · Document), 이름, tag (문서 = DocId)}. 내용은 종류마다 참여자 (IUndoParticipant —
   undoLast · redoLast · dropRedo) 가 자기 더미에 갖는다. 참여자는 편집을 기록할 때 record() 를 부르고, undo() 는 줄의 마지막 칸의
   참여자에게 시킨다 — 참여자의 더미와 줄의 그 종류 칸은 같은 차례. 참여자가 지금 못 하면 (월드 편집의 결과를 기다림) false — 줄 그대로
2. 새 기록은 다시 하기 줄을 비우고 모든 참여자에게 dropRedo (한 줄이므로 — 문서를 고치면 월드의 다시 하기도 사라진다).
   지우기: 종류 (월드가 바뀌면 World 만 — 10 12D 그대로) · 종류 + tag (문서를 닫거나 다시 읽으면 그 문서만). 상한 1000 칸 — 넘으면
   가장 오래된 칸을 버리고 센다
3. DocumentService: 편집 = 바이트 범위 바꾸기 {offset, 지울 길이, 넣을 글}, 범위 밖 · UTF-8 글자 가운데는 거절, 빈 편집은 칸을 만들지
   않는다. 편집마다 칸 하나 (타자 묶기는 UI 의 몫 — [계획]). 같은 경로 (정규화) = 같은 문서
4. 저장: 저장 전 검사 (확장자마다 — .json 은 JSON 으로 읽혀야, 그 밖은 setValidator — 내용 규칙은 sbx check 의 몫) → 바깥 변경 (열거나
   저장 · 다시 읽은 때의 디스크 SHA-256 과 지금 디스크가 다르면, 또는 파일이 없어졌으면 거절 — 덮어쓰지 않는다, force 면 쓴다) → 원자적
   쓰기 (io::writeFileAtomic). 고친 채로 닫기는 force 만. 다시 읽기는 고친 것 · 그 문서의 되돌리기 칸을 버린다
5. 월드 편집 (Editor 의 Undo) 을 World 참여자로 붙이는 것은 ST-06-1 (3) — 지금 Editor 는 자기 Ctrl+Z 를 그대로 쓴다
```

## 근거

```text
- 차례만 갖는 서비스: 월드 되돌리기는 역명령 · 결과 기다림 · IdRemap 이 필요하고 render 를 아는 Editor 에 있다. 내용을 서비스로 옮기면
  대규모 리팩터 (ADR-0089 4 금지) — 참여자 인터페이스 하나로 같은 Ctrl+Z 를 얻는다
- 디스크 해시로 바깥 변경: 수정 시각은 원자적 쓰기 · 복사 · 시계에 흔들린다. 바이트가 같으면 덮어써도 잃는 것이 없다
- 덮어쓰지 않는 기본: 다른 편집기 (VS Code) 에서 고친 팩 파일을 Studio 가 조용히 지우면 작업을 잃는다 (28 G8 — 작업을 잃지 않는다)
- 바이트 범위: UI (ImGui 여러 줄 칸 · 앞으로의 편집기) 가 고친 자리를 그대로 준다. 글자 단위는 27 9장 (텍스트 위치 계약) 이 정한다
```

## 결과

- 얻는 것: 파일 편집의 한 길 (검사 · 원자적 · 바깥 변경), 월드 · 파일이 섞인 하나의 Ctrl+Z 의 바탕, 헤드리스 시험.
- 비용: 편집마다 지운 글 · 넣은 글을 기억한다 (문서 전체 바꾸기는 문서 크기만큼 — 상한 1000 칸).
- 위험: 참여자의 더미와 줄이 어긋나면 엉뚱한 것을 되돌린다 — record 와 더미 넣기를 같은 함수에서 (DocumentService::apply), 지우기는
  참여자와 서비스가 같은 조건으로 (forget).

## 대안

| 대안                                       | 기각 사유                                                                   |
|--------------------------------------------|-----------------------------------------------------------------------------|
| 서비스가 모든 되돌리기 내용을 갖는다          | 월드 되돌리기 (역명령 · IdRemap · 결과 기다림) 를 render 없는 층으로 옮기는 대규모 리팩터 |
| 문서마다 따로 Ctrl+Z                         | 25 · 사용자 기대 (하나의 Ctrl+Z) 와 다르다 — 편집기 칸 안의 되돌리기는 UI 가 따로 둘 수 있다 |
| 수정 시각으로 바깥 변경                        | 원자적 쓰기 · 복사 · 시계 차이에 흔들린다                                    |
| 바깥 변경이면 자동 다시 읽기                   | 고친 것을 조용히 잃는다 — 사용자가 고른다 (다시 읽기 · 강제 저장)           |

## 재검토 조건

월드 참여자 붙이기 (ST-06-1 (3)), 타자 묶기 · 편집기 (M6-T8), 파일 감시 (OS 알림 — 지금은 저장 · 묻기 때 해시), 자동 저장 (M6-T7).
