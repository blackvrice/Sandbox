# ADR-0022. 지형은 타일 머티리얼 번호 텍스처 + 팔레트로 한 번에 그리고, 격자 · 선택 · 디버그는 화면 픽셀 기준 오버레이로, 패스별 GPU 시간은 프레임 슬롯 타임스탬프로 잰다

- 상태: **Accepted** · 날짜: 2026-10-07
- 관련: [06-RENDERING](../06-RENDERING.md) 8 · 13 · 14장, [16-ROADMAP](../16-ROADMAP.md) Phase 8 (8.3 · 8.6),
  [ADR-0020](0020-sprite-atlas-instancing-direct-sim-presentation.md), [ADR-0021](0021-direct-sim-simulation-thread-snapshot.md)

## 맥락

Phase 8B 는 8.3 (TerrainPass · DebugDraw · GridPass · SelectionPass)과 8.6 (지표 · 타임스탬프 쿼리)이다. 8A 까지 월드는
경계 크기의 단색 배경 스프라이트 위에 개체만 그렸다 — 호수 · 흙 같은 지형이 보이지 않았다. 정할 것:

```text
1. 지형 그리기: 06 8.3 의 "청크 메시 캐시" 를 그대로 (청크마다 타일 사각형 정점) 할지
2. 지형 데이터를 Simulation 스레드 → Render 쪽으로 어떻게 (ADR-0021 의 스냅숏은 틱마다)
3. 격자 · 선택 외곽선 · 디버그 선: 줌이 0.25 ~ 512 px/칸 이라 월드 두께 선은 사라지거나 뭉개진다
4. 선택은 어디서 (월드는 Simulation 스레드만 읽는다 — T1)
5. GPU 타임스탬프: RHI 모양, 언제 읽는가 (GPU 를 기다리지 않고)
```

## 결정

```text
1. 지형 = 텍스처 두 장 + Draw 1개 (TerrainPass)
     tiles    R16 UINT (월드 타일 수 크기 — 최대 64 × 32 = 2048²), 텍셀 = 머티리얼 번호
     palette  RGBA8 1 행, 번호 → 색 ("terrain/<머티리얼 id>" — MaterialLibrary, 없으면 이름 해시 색)
   월드 격자를 덮는 사각형 하나를 그리고 픽셀마다 tiles.Load → palette.Load (가장 가까운 타일, 필터 없음).
   확대했을 때만 타일마다 밝기 ±4 % 결 (축소하면 픽셀보다 작은 타일이 반짝이므로 ppu 4 ~ 12 에서 서서히).
   revision 이 바뀐 청크만 그 영역을 업로드 링 → copyBufferToTexture (프레임 예산 4 MB ≈ 512 청크).
   "청크 메시 캐시"(P5)의 목적 — 바뀐 청크만 다시 만든다 — 은 같고, 정점이 없어 청크 수와 무관하게 Draw 1개다.
2. Extraction 의 capture 가 청크마다 머티리얼 번호를 revision 이 바뀔 때만 shared_ptr<const vector<u16>> 로 복사한다.
   바뀌지 않은 청크는 이전 스냅숏과 같은 버퍼를 공유 — 틱마다 지형을 복사하지 않는다. RenderWorld.terrain 은
   (worldId, 청크 크기 · 범위, 청크 목록, 팔레트 + 버전). TerrainPass 는 worldId · 범위가 바뀌면 텍스처를 다시 만든다.
3. 오버레이는 화면 픽셀 두께
     GridPass       월드 격자를 덮는 사각형 하나, 픽셀 셰이더가 가장 가까운 선까지의 화면 거리로 그린다 —
                    타일 선(타일이 6 px 이상일 때 서서히), 청크 선, 월드 경계(금색). 선마다 정점이 없다
     LinePass       선마다 인스턴스 하나 (24 바이트: 두 끝점 · 색 · 두께 px), 정점 셰이더가 화면에서 두께만큼 넓힌다,
                    가장자리 1 px 알파. SelectionPass(선택 외곽선 · 끄는 중의 박스)와 DebugPass(감지 반경 · 경로 ·
                    목표 · 대상 · 속도)가 같은 파이프라인을 쓰고 Draw 를 하나씩
     DebugDrawList  line · rect · box(회전) · circle · arrow · polyline — 순수 CPU, 프레임마다 다시 채운다
4. 선택은 Main 스레드가 스냅숏에서 고른다 (pickAt = 맨 위에 그려진 개체 — 레이어 → depth, pickBox = 가운데가 안에 든 것).
   선택 목록(saveId 오름차순)은 DirectSim 이 들고, capture 때 Simulation 스레드가 선택한 개체(최대 32)의 자세한 상태
   (프리팹 · 행동 상태 · 에너지 · 체력 · 감지 반경 · 남은 경로 · 목표 · 대상 위치 · 속도)를 스냅숏에 담는다.
   일시정지 중 선택이 바뀌면 진행 없이 다시 capture 한다. 죽은 개체는 Main 이 다음 프레임에 선택에서 뺀다.
   조작: 왼쪽 클릭 = 점, 왼쪽 끌기(4 px 넘게) = 박스, Shift = 더하기(이미 있으면 빼기), Esc = 해제, G = 격자,
   V = 자세히(기본 켬). 카메라 끌기는 가운데 버튼만 (8A 의 왼쪽 끌기 카메라는 선택에 내줬다).
5. 타임스탬프 = 프레임 슬롯마다 32 칸
     ICommandList::writeTimestamp(i) · resolveTimestamps(n)   (D3D12: 쿼리 힙 framesInFlight × 32, Readback 버퍼 영구 매핑)
     IRenderDevice::completedTimestamps()   beginFrame 이 슬롯을 다시 쓰기 전에 그 슬롯의 값을 옮겨 둔다 —
                                            보통 framesInFlight 프레임 전의 값. GPU 를 기다리지 않는다
   Renderer 는 칸 7개: 시작 · 업로드 끝 · 지형 · 스프라이트 · 격자 · 선택 · 디버그 → RendererStats.gpu (패스별 ms).
   자기가 쓴 프레임의 값만 쓴다 (다른 코드가 쓴 타임스탬프와 섞이지 않게).
   지표는 제목 줄에 "GPU 1.2 ms (지형 · 스프라이트 · 격자 · 선)" — 화면 오버레이 글자는 ImGui(8C).
```

그 밖에 작게 정한 것:

```text
- 그리기 순서는 한 렌더 패스 안: Clear → Terrain → WorldSprite → Grid → Selection → Debug (06 8.4 의 순서).
  배경 스프라이트(8A)는 없앴다 — 지형이 월드 경계를 덮는다.
- Format::R16Uint 를 추가했다 (정수 텍스처 — 셰이더는 Load 로만). 열거 끝에 붙여 기존 값은 그대로.
- 지형 텍스처 행 0 = 월드 아래쪽 (청크 안 행 순서 그대로) — 화면에 직접 보이지 않으므로 terrain.hlsl 과 업로드만 맞으면 된다.
- 없는 머티리얼 번호(팔레트 밖)는 마젠타 — 8A 의 실패 스프라이트와 같은 신호.
```

## 근거

```text
- 탑다운 타일 지형은 타일 하나 = 텍셀 하나로 충분하다. 정점 메시는 64 × 64 청크 × 1,024 타일 = 4M 사각형을 만들고 바뀔 때마다
  다시 올려야 한다. 텍스처는 2048² × 2 바이트 = 8 MB 한 장, 청크 갱신은 8 KB 영역 복사다.
- 텍셀 Load 는 필터가 없어 구현(WARP · lavapipe · GPU)마다 같은 값이 나온다 — 기준 이미지 terrain 이 픽셀 단위로 맞다.
- 화면 픽셀 두께가 아니면 512 px/칸 확대에서 선이 수십 px 이 되고, 0.25 px/칸 축소에서 사라진다. 격자를 정점으로 만들면
  2048 타일 경계 × 2 축 = 4,096 선 — 셰이더 계산이 Draw 1개로 같은 일을 한다.
- 선택을 Simulation 스레드에서 고르면 클릭 → 결과가 틱을 기다린다 (Debug 에서 100 ms). 스냅숏은 화면에 보이는 그대로라
  보이는 것을 고르는 게 맞다. 자세한 상태만 Simulation 이 채운다 (T1).
- 슬롯마다 칸을 따로 두면 resolve 결과를 beginFrame 의 펜스 대기(이미 하는 일)만으로 안전하게 읽는다 — 추가 동기화 0.
```

## 결과

- 얻는 것: 호수 · 흙이 보이는 지형, G 격자, 클릭 · 박스 선택과 선택한 개체의 감지 반경 · 경로 · 대상 · 속도, 패스별 GPU ms.
  기준 이미지 terrain · overlay, GPU 테스트 timestamps · gpu timings, 단위 테스트(도형 · 선 컬링 · TerrainCache · 고르기 ·
  앱 입력).
- 포기하는 것: 지형 타일 그림(텍스처 아틀라스의 풀 · 물 그림 — 지금은 색), 경계 섞기(물가 · 흙 가장자리), 높이.
  타일 하나보다 작은 화면(ppu < 1)에서 축소 앨리어싱 (밉맵 없음).
- 위험: 지형 텍스처는 월드 크기에 비례 — 고정 경계 상한(64 청크)이면 8 MB. 스트리밍 월드(05-WORLD [후속])에서는 보이는
  청크만 담는 고리 텍스처로 바꿔야 한다. 타임스탬프가 없는 어댑터(caps.timestampQueries = false)는 GPU 시간을 안 보인다.

## 대안

| 대안                                           | 기각 사유                                                                     |
|------------------------------------------------|-------------------------------------------------------------------------------|
| 청크마다 타일 사각형 정점 메시 (06 P5 초안)    | 정점 4M · 청크마다 Draw 또는 큰 업로드. 같은 결과를 텍스처 한 장이 낸다       |
| 지형을 스프라이트(타일당 하나)로               | 2048² = 4M 인스턴스                                                           |
| 지형 텍스처를 청크마다 Texture2DArray 층으로   | 층 수 상한 2048, 층마다 사각형 — 경계에서 필터 · 이음매. 한 장이면 경계가 없다 |
| 격자 · 선을 월드 두께 사각형(스프라이트)으로   | 줌에 따라 사라지거나 굵어진다                                                 |
| 선택을 Simulation 스레드에서 (명령처럼)        | 클릭 응답이 틱 시간에 묶인다, 보이는 것과 다른 것을 고를 수 있다               |
| 타임스탬프를 매 프레임 GPU 를 기다려 읽기      | 프레임마다 CPU 가 GPU 를 기다린다 (파이프라인이 깨진다)                        |

## 재검토 조건

지형 그림(타일 아틀라스 · 경계 섞기 — 콘텐츠가 그림을 원할 때), 스트리밍 월드(Phase 4 [후속]), Vulkan(Phase 13: 쿼리 풀 ·
R16_UINT 샘플), 에디터 지형 칠하기(Phase 12 — 칠할 때마다 청크 revision 이 오르므로 업로드 예산을 다시 본다), ImGui(8C —
지표를 화면 글자로).
