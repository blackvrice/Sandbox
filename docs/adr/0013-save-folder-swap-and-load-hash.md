# ADR-0013. 세이브는 폴더째 바꿔 넣고, 로드는 해시로 스스로 검증한다

- 상태: **Accepted** (2번의 Opaque 건너뛰기 조건은 [ADR-0014](0014-content-model-spawnqueue-name-tables.md) 3번이 대체) · 날짜: 2026-10-05
- 관련: [09-SERIALIZATION](../09-SERIALIZATION.md) 3장, [04-DETERMINISM](../04-DETERMINISM.md) D2, [05-WORLD](../05-WORLD.md) 3.2

## 맥락

세이브는 여러 파일(world.json, entities.jsonl, chunks/*.chunk)이다. 문서 초안은 "파일마다 임시 파일 → 원자적 rename" 이었다.
그러면 파일 하나하나는 온전하지만 **세트**는 아니다: world.json 은 새 것인데 entities.jsonl 은 옛 것인 순간이 생기고,
지난 세이브에만 있던 청크 파일이 폴더에 남아 다음 로드에 섞인다 (청크 파일은 손댄 청크만 쓰므로).

로드한 월드가 저장한 월드와 같은지는 D2 의 핵심인데, 지금까지 그것을 확인하는 곳은 `sbx_sim_check --save-at` 뿐이었다.

## 결정

```text
1. 저장 = <dir>.saving 에 모든 파일을 쓴 뒤 폴더 교체: <dir> → <dir>.old, <dir>.saving → <dir>, <dir>.old 삭제.
   교체 직전까지 실패하면 이전 세이브는 그대로다. 두 rename 사이에서 실패하면 <dir>.old 에 이전 세이브가 남는다(오류에 경로).
2. world.json 에 저장 시점 worldHash 를 기록하고, 로드는 다시 계산한 해시와 비교해 다르면 실패한다 (D2 를 모든 로드에서).
   단 비교가 정의상 의미 없는 경우는 건너뛰고 이유를 돌려준다:
     simVersion 이 다름 · 컴포넌트 마이그레이션 적용 · 이번 로드에 Opaque 가 있음 · 저장한 프로세스에 Opaque 가 있었음.
3. 지형 머티리얼은 세이브에 인덱스 + id 표로 저장하고, 해시는 인덱스가 아니라 id 의 stableId 로 먹인다.
   그래서 콘텐츠의 머티리얼 순서가 바뀌어도 재매핑 후 해시가 같고 2번 검증이 그대로 성립한다.
```

## 근거

```text
- 폴더 교체는 POSIX·Windows 모두 rename 두 번이다. 파일 세트 일관성과 잔재 정리를 한 번에 해결한다.
- 로드 시 해시 비교는 비용이 작다 (해시 1회) 대신 "세이브에 빠진 상태"를 저장 직후가 아니라 **매 로드**에서 잡는다.
  RTS 에서 세이브 왕복 후 조용히 달라지는 버그가 늦게 발견된 경험을 구조로 막는다 (04 H3 와 같은 취지).
- 인덱스로 해시하면 콘텐츠 순서 변경 → 해시 변경 → 2번이 거짓 경보가 된다. id 해시는 머티리얼 수(수 개)만큼의 표로 충분하다.
```

## 결과

- 얻는 것: 반쯤 쓴 세이브·섞인 청크 파일이 없다. 모든 로드가 D2 를 확인한다. 콘텐츠 순서에 강하다.
- 포기하는 것: 매 저장이 모든 파일을 다시 쓴다 (증분 저장 불가 — 50k 에서 약 0.2 s). 저장 중 디스크 사용량이 2배.
- 위험: 바이러스 백신·탐색기가 폴더를 잡고 있으면 Windows 에서 rename 이 실패할 수 있다 → 오류로 보고되고 이전 세이브는 남는다.

## 대안

| 대안 | 기각 사유 |
|---|---|
| 파일마다 원자적 rename (초안) | 세트 불일치·잔재 청크 파일 |
| 증분 저장 (바뀐 청크만) | 같은 폴더에 다른 월드를 저장할 때 revision 비교만으로는 잔재를 구분할 수 없다. 메모리의 "마지막 저장 revision" 장부와 함께 Phase 9 오토세이브에서 다시 본다 |
| 로드 해시를 경고만 | D2 위반은 데이터 손실이다. 조용히 넘기면 RTS 와 같은 늦은 발견이 된다 |

## 재검토 조건

오토세이브(Phase 9)에서 저장 시간이 틱 예산을 위협할 때 — 증분 저장과 Worker 직렬화를 이 결정 위에 얹는다.
