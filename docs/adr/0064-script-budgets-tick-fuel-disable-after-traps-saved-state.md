# ADR-0064. 스크립트 예산 · 트랩 정책 — 호출 · 틱 예산, 트랩 3 번 이어지면 시스템을 끈다 (세이브에 남기고 바이트코드가 바뀌면 다시 켠다), 시스템별 통계

- 상태: **Accepted** · 날짜: 2026-10-26
- 관련: [ADR-0062](0062-script-systems-define-system-stage-16b-pack-id-order.md) (16b · 트랩이면 그 호출만 버림), [ADR-0063](0063-script-callbacks-start-stop-event-stage-17d-same-tick.md)
  (17d · eventsPerTick), [ADR-0056](0056-sandboxscript-language-subset-own-compiler-no-gc.md) 5 (트랩), [ADR-0060](0060-script-component-host-read-query-write-buffer-entity-handles.md)
  (질의 · 쓰기 상한), [04-DETERMINISM](../04-DETERMINISM.md), [09-SERIALIZATION](../09-SERIALIZATION.md) 2장, [19-SANDBOXSCRIPT](../19-SANDBOXSCRIPT.md) 19장,
  [18-PLATFORM](../18-PLATFORM.md) 6.2 (v0.3 M4-T3)

## 맥락

호출 하나는 VM 예산 (연료 1,000,000 · 아레나 4 MiB · 깊이 · 칸) 으로 멈추지만, 시스템이 많으면 한 틱이 시스템 수 × 1,000,000 명령을
돌 수 있다. 계속 트랩이 나는 시스템은 틱마다 연료를 다 쓰고 쓰기를 버린다. ctx.log 는 줄 수에 상한이 없다. 초안: "fuel · 메모리 ·
스택 · spawn · 이벤트 · 질의 · HostCall 제한, 서버 틱의 상한, 시스템별 통계, 실행 중단 시 정책". 정할 것: 예산의 단위 (호출 · 틱),
넘으면 무엇을 하나, 시스템을 끄는 기준, 끈 상태를 어디에 두나, 무엇을 세나.

## 결정

```text
1. 호출 예산 (호출 하나 — 넘으면 트랩, 그 호출의 쓰기를 버린다):
     연료 1,000,000 · 아레나 4 MiB · 깊이 128 · 칸 2^18 · 배열 2^20 · 문자열 1 MiB (VM — 19 13장)
     Host 호출 65,536 번 (vm::Limits::maxHostCalls — 넘으면 HostError)
     질의 하나의 개체 65,536 · 쓰기 65,536 (ScriptHost — ADR-0060)
2. 틱 예산 (16b + 17d 의 모든 스크립트 호출 합):
     연료 4,000,000 — 호출마다 min(1,000,000, 남은 연료) 로 돈다. 남은 연료로 멈춘 호출 (틱 예산 때문의 OutOfFuel) 은 쓰기를
     버리고 "예산" 으로 센다 (트랩 정책에 넣지 않는다 — 그 시스템의 잘못이 아니다). 남은 연료가 0 이면 그 틱의 남은 호출은
     건너뛴다 (cut). 연료는 결정적이라 어디서 끊기는지도 결정적이다
     onEvent — 시스템마다 eventsPerTick, 틱 4,096 (ADR-0063)
     ctx.log — 틱 256 줄 (넘으면 버리고 센다 — 로그는 시뮬레이션 상태가 아니다)
3. 트랩 정책: 한 시스템의 호출 (콜백 무엇이든) 이 트랩으로 3 번 이어지면 그 시스템을 끈다 — 그 틱의 남은 호출부터 부르지 않는다.
   트랩 없이 끝난 호출이 이어짐을 0 으로. 예산으로 끊긴 호출 · 건너뛴 호출은 세지 않는다. 끌 때 경고 한 줄
4. 끈 상태 · 이어진 트랩 수 = 시뮬레이션 상태 → 세이브 world.json "scriptSystems" (기본값이 아닌 시스템만 — 없으면 키 없음):
     [{ "id": "rpg.mana.regen", "digest": "0x…", "traps": 2, "disabled": false }]
   digest = 그 팩 바이트코드 (bc::serialize) 의 FNV-1a 64. 로드할 때 같은 id · 같은 digest 면 되살리고, digest 가 다르면 (스크립트를
   고쳤다) 버리고 다시 켠다 · 없는 시스템이면 버린다 — 둘 다 로드 경고. WorldHash 에는 넣지 않는다 (끈 시스템의 차이는 그 뒤
   컴포넌트 값으로 드러난다). schemaVersion 그대로 (선택 키)
5. 시스템별 통계 (진단 — 세이브 · 해시에 없음, 로드하면 0 부터): 호출 · 트랩 · 예산 · 건너뜀 (cut) · 연료 합 · 호출 하나의 최대 연료 ·
   마지막 트랩 글 · 꺼짐. 틱 통계 (lastStats) 에 틱 연료 · 버린 로그. 서버 · sbx_sim_check 가 끝날 때 시스템마다 한 줄
```

## 근거

```text
- 틱 연료: 30 TPS 의 틱 시간을 스크립트가 다 쓰지 못하게 한다. 4,000,000 은 Release VM 에서 수 ms 대 (명령당 수 ns — M6 벤치로
  맞춘다), 호출 하나의 1,000,000 보다 넉넉해 시스템 넷이 한 번씩 상한까지 돌 수 있다
- 틱 예산 OutOfFuel 을 트랩 정책에서 빼기: 앞 시스템이 연료를 다 써서 뒤 시스템이 끊겨도 뒤 시스템은 꺼지지 않는다
- 3 번 이어짐: 한 번의 트랩은 드문 입력 (빈 질의 · 0 으로 나누기) 일 수 있다. 이어지면 버그 — 틱마다 연료를 태우고 로그를 쓰는
  시스템을 멈춘다. 횟수 · 창 (N 틱 안에 M 번) 은 상태가 늘어 단순한 쪽을 골랐다
- 끈 상태를 세이브에: 세이브 → 로드한 월드가 끈 시스템을 다시 켜면 두 월드가 갈린다 (D2). digest 로 다시 켜기: 고친 스크립트로
  다시 열면 손으로 켤 일이 없다 (켜고 끄는 명령은 에디터와 함께 [계획 M5])
- 로그 상한: ctx.log 를 도는 루프가 서버 로그를 채우지 못하게. 상태가 아니라 틱 안에서 센다
```

## 결과

- 얻는 것: 스크립트가 틱 시간 · 로그를 무한히 쓰지 못한다, 계속 망가진 시스템이 스스로 멈춘다, 세이브 → 로드가 그 상태를 지킨다,
  시스템마다 비용 · 문제를 본다.
- 포기하는 것: 시스템마다 다른 예산 (모두 같은 상수 — 키는 [검토 M6 벤치 뒤]), 끈 시스템을 손으로 켜기 (에디터 · 명령 [계획 M5]),
  예산의 실제 시간 기준 (연료는 명령 수 — 시간은 바이너리 · 기계마다 다르다).
- 위험: 틱 예산이 콘텐츠에 비해 작으면 뒤 팩의 시스템이 늘 끊긴다 — 완화: 시스템별 "예산" · "건너뜀" 통계와 끝 줄.

## 대안

| 대안                                          | 기각 사유                                                                       |
|-----------------------------------------------|---------------------------------------------------------------------------------|
| 틱 예산 없이 호출 예산만                     | 시스템 수만큼 틱이 길어진다                                                      |
| 벽시계 시간으로 끊기                          | 결정론 위반 (04) — 서버마다 다른 자리에서 끊긴다                                  |
| 트랩 한 번에 끄기                             | 드문 입력 하나로 게임 규칙이 사라진다                                            |
| 끈 상태를 메모리에만                          | 세이브 → 로드 뒤 다시 켜져 두 월드가 갈린다 (D2)                                  |
| 끈 상태를 해시에                              | 해시 형식이 바뀐다 — 차이는 어차피 컴포넌트로 드러난다                             |
| 팩의 모든 시스템을 같이 끄기                  | 한 시스템의 버그가 다른 규칙까지 멈춘다                                           |

## 재검토 조건

M6 벤치 (10k 대상) 에서 틱 연료가 실제 틱 시간과 맞지 않을 때 (상수 조정 · 시스템별 키), 에디터가 시스템을 켜고 끄는 명령을 요구할
때 (M5), 서버 운영자가 끄는 대신 세션 종료 · 경보를 원할 때.
