# ADR-0124. 바이트코드 줄 표 (.sbc 형식 11) — 함수마다 (pc, 줄, 열), 트랩 자리는 파일:줄:열

- 상태: **Accepted** · 날짜: 2026-11-11
- 관련: [ADR-0058](0058-bytecode-register-machine-typed-registers-verifier.md) (바이트코드 · 검증기), [19-SANDBOXSCRIPT](../19-SANDBOXSCRIPT.md) 12장, [27-SCRIPT-IDE](../27-SCRIPT-IDE.md) 3 · 5장,
  task-registry M6-T4 (조각 1)

## 맥락

트랩은 함수 이름 · pc 로만 알렸다 ("eco/scripts/a.ts:onTick pc 17"). 사람이 소스에서 그 자리를 찾을 수 없고, 프로파일 · 재생 디버거
(ST-06-7) · 편집기의 줄 이동 (M6-T8) 이 같은 표를 기다린다 (27 3장).

## 결정

```text
1. bc::Function.lines = (pc, 줄, 열) 칸 — 그 pc 부터 다음 칸 앞까지의 명령이 온 소스 자리. pc 오름차순 (같은 pc 없음), 줄 · 열은 1 부터,
   열 = 코드 포인트 (Diagnostic 의 SourcePos 와 같은 단위). 파일은 함수 이름 앞부분 (따로 싣지 않는다)
2. 코드 생성이 문장 · 식 마디에 들어갈 때 자리를 바꾸고 (RAII — 나오면 바깥 자리), emit 이 자리가 바뀔 때만 칸을 더한다. 호출은 '(' 대신
   부른 이름의 첫 글자. 함수 머리 = 매개변수 · 마지막 RET
3. 파일: 함수마다 명령 뒤에 개수 + u32 셋. 읽기가 모양을 본다 (개수 ≤ 명령 수 · pc 오름차순 · 명령 안 · 줄 · 열 ≥ 1 — 아니면 ParseError).
   형식 10 → 11 (옛 형식 VersionMismatch — .sbc 는 디스크에 없고 소스에서 다시 컴파일)
4. 실행 · 검증은 줄 표를 보지 않는다 — 자리만. 결정론 · WorldHash 영향 없음 (kSimVersion 그대로)
5. 트랩 자리 = bc::describeSite: "scripts/a.ts:12:5 (clamp)", 줄 표가 없으면 (손으로 만든 모듈) "scripts/a.ts:clamp pc 3"
```

## 근거

```text
- 식 단위 (문장 단위가 아니라): 한 줄에 xs[i] · idiv · 호출이 같이 있어도 트랩 열이 맞는다. 값은 메모리 2.3 KB (명령 256 개 시험 프로그램)
- 델타 · varint 압축 안 함: .sbc 를 파일로 나르지 않는다 — 단순한 고정 크기가 읽기 검사를 쉽게 한다 (믿지 않는 바이트)
- 파일 이름을 칸마다 싣지 않음: 함수 하나 = 파일 하나 (검사기의 함수는 한 모듈 파일에 있다)
```

## 결과

- 얻는 것: 트랩 로그 · lastTrap 에 파일:줄:열, 프로파일 · 디버거 · 편집기 줄 이동이 쓸 표.
- 포기하는 것: 모듈 바이트가 커진다 (시험 프로그램 +46 % — 메모리에만), 세이브의 스크립트 시스템 상태 (트랩 수 · 꺼짐) 는 모듈 digest 가 바뀌어
  업그레이드 뒤 첫 로드에서 0 부터.
- 위험: 열 단위가 코드 포인트 — 편집기 (UTF-16 · 화면 열) 로의 변환은 NG-05 텍스트 위치 계약이 맡는다.

## 대안

| 대안 | 기각 사유 |
|------|-----------|
| 문장 단위 줄만 | 같은 줄의 여러 트랩 자리를 가르지 못한다 |
| 명령마다 자리 (칸 = 명령 수) | 같은 자리의 이어진 명령이 많아 낭비 — 바뀔 때만 |
| 디버그 정보를 따로 (사이드카 파일) | .sbc 를 파일로 나르지 않으니 나눌 이유가 없다 |

## 재검토 조건

.sbc 를 패키지에 싣게 되면 (소스 없는 배포) 압축 · 사이드카, 열 단위를 화면 열로 바꿀 때 (NG-05).
