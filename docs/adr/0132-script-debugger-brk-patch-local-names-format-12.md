# ADR-0132. 스크립트 디버거의 VM 쪽 — BRK 패치 (중단점이 없으면 비용 0), 지역 이름 표 (.sbc 형식 12), 단계 · logpoint · 감시 식

- 상태: **Accepted** · 날짜: 2026-11-12
- 관련: [27-SCRIPT-IDE](../27-SCRIPT-IDE.md) 6장 (방식 B — 결정적 재생 위 디버깅), [ADR-0124](0124-bytecode-line-table-format-11.md) (줄 표),
  [ADR-0125](0125-script-function-profile-self-fuel-protocol-18.md) (프로파일), [ADR-0127](0127-script-executor-interface-pack-kind-conformance.md)
  (실행자), task-registry ST-06-7 (조각 1)

## 맥락

재생 디버거 (ST-06-7) 는 리플레이를 디버그 프로세스에서 다시 돌려 스크립트 콜백 안에서 멈춘다 (27 6장의 방식 B). 완료 기준은 "재생 중단 ·
같은 해시 · 훅 비용 < 2 %" — 디버거가 없을 때 인터프리터 실행 루프가 느려지면 안 된다 (명령마다 "중단점인가" 를 보는 분기는 핫 루프에
비용). 멈춘 자리에서 지역 값을 보려면 레지스터 → 소스 이름이 필요한데 바이트코드에는 줄 표만 있다.

## 결정

```text
1. 중단점 = BRK 패치 (네이티브 디버거의 int3 와 같은 방식): 디버그 세션은 모듈의 사본을 갖고 멈출 자리의 명령을 BRK 로 바꾼다 (원래 명령은
   vm::CodePatches — 자리마다 주인 비트: 사용자 중단점 · 단계). 인터프리터의 BRK 칸이 IDebugHook 을 부르고 원래 명령을 돌린다 (연료는 한 번 —
   switch 앞에서 낸 것). 디버거가 없을 때의 비용 = switch 의 칸 하나 (명령마다 검사 없음)
2. BRK 는 디버그 세션의 사본에만: 검증기가 거절한다 (파일 · 컴파일 결과에는 없다). 디버거 없이 만나면 Unreachable 트랩. 인터프리터는 검증된
   모듈로 만든 뒤에 BRK 를 놓는다
3. 지역 이름 표 (형식 11 → 12): 함수마다 {레지스터, 이름, pc [begin, end)} — 매개변수 · const · let · for-of 변수 (코드 생성은 지역의
   레지스터를 다시 쓰지 않는다 — 임시만 다시 쓴다). 선언 뒤부터 둘러싼 블록 · 문장 끝까지. 읽기가 모양을 본다 (레지스터 안 · 범위가 명령 안 ·
   이름 1 ~ 256 바이트). 실행 · 검증은 보지 않는다 — 결정론 · WorldHash 영향 없음 (kSimVersion 그대로). 옛 형식은 VersionMismatch (소스에서
   다시 컴파일 — .sbc 는 디스크에 없다)
4. 중단점의 자리 = 파일 · 줄 → 그 줄에 코드가 있는 함수마다 그 줄의 첫 명령 (줄 표). logpoint = 멈추지 않고 "{식}" 을 채운 글을 남긴다
5. 단계: Into = 모든 함수의 줄 시작 (줄 표에서 줄이 바뀌는 칸) 에 단계 BRK, Over = 스택의 함수들의 줄 시작 (더 깊은 프레임은 멈춤 조건이
   지나간다), Out = 바깥 프레임들의 줄 시작 (지금 깊이 이상은 지나간다). 멈추면 단계 BRK 를 모두 거둔다. armStep = 다음 호출의 첫 줄에서
6. 보기: 프레임 (0 = 바깥 — 바깥의 pc 는 부른 명령), 그 pc 에서 보이는 지역, 값 글 (구조체는 필드 이름 순 · 깊이 2 · 원소 8 까지, 문자열
   120 바이트, 타입 이름은 구조적 — 바이트코드에 구조체 이름이 없다), 감시 식 = 지역 이름 뒤 .필드 · [정수] · .length 만 (읽기만 — 식 평가기 ·
   Host 호출 없음: 재생을 바꿀 수 없다)
7. 훅은 읽기만 — 붙여도 호출 결과 · 연료 · 프로파일이 같다 (시험). 재생 세션 · 같은 WorldHash · Studio 창은 조각 2 · 3
```

## 근거

```text
- BRK 패치: "분기 하나도 없는 별도 루프" (27 6장) 를 루프를 둘로 복제하지 않고 얻는다 — 2,900 줄 실행 루프를 둘로 유지하는 비용이 없다
- 측정 (Release sbx_bench --only script, 같은 머신에서 이전 · 이후 바이너리를 번갈아 6 번 — 최솟값 / 중앙값): script.regen 16.34 → 16.52 ms
  (+1.1 % / +0.4 %), merge sort n=100000 98.1 → 98.3 ms (+0.2 % / +6.2 %), n=10000 7.97 → 7.73 ms (−3.0 % / −3.1 %). 이 머신의 반복 잡음이
  ±5 ~ 10 % (sortNumbers 가 같은 코드로 −22 ~ +13 %) — 회귀는 잡음 안이고 최솟값 기준 < 2 %
- 지역 이름 표를 형식에: 디버거가 멈출 때 소스를 다시 컴파일해 이름을 맞추는 길은 바이트코드와 소스가 어긋날 수 있다 (Hot Reload)
- 감시 식을 경로로만: 식 평가기는 부작용 (호출 · 대입) 을 막는 별도 검사기가 필요하다 — 읽기 경로로 충분한 것부터
```

## 결과

- 얻는 것: 중단점 · logpoint · Into/Over/Out · 프레임 · 지역 값 · 감시 경로, 디버거 없을 때 비용 없음, 결과 불변 시험.
- 포기하는 것: 조건부 중단점 · 식 평가 (산술 · 호출), 한 줄 반복문 안의 Over (같은 줄로 돌아오면 멈추지 않는다), 값 바꾸기 (재생을 바꾼다 —
  하지 않는다), 구조체 이름 (구조적 타입으로 보인다).
- 위험: 단계 Into 는 모든 함수의 줄 시작에 BRK 를 놓는다 — 큰 팩에서 단계 중의 속도가 떨어진다 (멈출 때까지만).

## 대안

| 대안 | 기각 사유 |
|------|-----------|
| 명령마다 "중단점 표가 비었나" 검사 | 핫 루프에 분기 — 완료 기준 (< 2 %) 을 위협한다 |
| 디버그용 실행 루프 복제 | 2,900 줄 루프 두 벌을 같게 유지해야 한다 |
| 멈출 때 소스를 다시 컴파일해 지역 이름 | 소스 · 바이트코드가 다를 수 있다 (오버레이 · Hot Reload) |
| 감시 = 작은 식 평가기 | 부작용 차단 · 타입 규칙이 또 하나 — 경로로 먼저 |

## 재검토 조건

조건부 중단점 · 식 감시 요구, 단계 Into 의 속도 문제 (함수 단위로 단계 BRK 를 늦게 놓기), JIT 실행자 (ADR-0127 — BRK 를 어떻게 다룰지).
