# ADR-0131. 스크립트 [적용 (오버레이)] / [저장 (팩 파일)] 구분 — 저장은 DocumentService, 줄 끝은 파일의 것, 바깥 변경은 묻는다

- 상태: **Accepted** · 날짜: 2026-11-11
- 관련: [ADR-0066](0066-script-overlay-kind-recompile-same-components-protocol-13.md) (스크립트 오버레이), [ADR-0109](0109-document-service-unified-undo-line.md)
  (DocumentService · 되돌리기 줄), [ADR-0128](0128-text-position-contract-byte-offset-ime-area.md) 5 (줄 끝 보존), [ADR-0130](0130-script-editor-widget-imgui-input-assist-service.md)
  (편집기 위젯), [27-SCRIPT-IDE](../27-SCRIPT-IDE.md) 0 · 8 · 9장, task-registry M6-T8 (조각 3)

## 맥락

콘텐츠 창의 스크립트는 [적용] 하나뿐이었다 — 월드 오버레이 (EditContent → 서버가 팩을 다시 컴파일). 고친 것은 월드 (세이브) 에만 남고 팩 파일은
그대로라, 다음에 다른 월드를 열면 사라진다. 오버레이 값은 16 KB 상한이라 큰 스크립트는 적용조차 못 한다. M6-T8 은 "지금 월드에 적용" 과 "팩
파일에 저장" 을 나눠 보이라고 한다 (20 10장 흐름 8 · G4). 편집기 (ImGui) 는 Enter 에 LF 를 넣어, CRLF 파일을 그대로 쓰면 줄 끝이 섞인다.

## 결정

```text
1. 단추 둘: [적용 (오버레이)] = 지금 월드 (그대로 — ADR-0066), [저장 (팩 파일)] = 이 컴퓨터의 팩 폴더 / scripts/… 파일 (다음 로드부터).
   둘은 따로다 — 저장이 오버레이를 빼거나 적용하지 않는다 (창의 안내 줄이 말한다). 머리 줄에 "팩 파일과 같음 · 다름 · 없음"
2. 팩 폴더 = ContentSourcePack::dir (로더가 읽은 폴더 — 새 필드, 해시 밖). 설치한 패키지 (.sandbox/packages/) 의 파일 · 폴더를 모르는 팩은
   쓰지 않는다 (프로젝트 팩에서 고치거나 적용)
3. 쓰기는 editor/services 의 saveScriptFile → DocumentService (원자적 — 임시 파일 → 이름 바꾸기). Application 이 DocumentService 하나를
   갖고 콘텐츠 창에 넣는다. 되돌리기 줄에는 넣지 않는다 — 편집기 칸이 제 되돌리기를 갖고, 저장은 되돌리기 칸이 아니다
4. 줄 끝: base (이 창의 마지막 저장 · 없으면 팩을 읽은 때의 원문) 의 줄 끝으로 글 전체를 맞춘다 (applyLineEnding — LF · CRLF · CR,
   섞였거나 한 줄이면 그대로). 새 파일은 편집기 글 그대로 (LF)
5. 바깥 변경: 디스크가 base 와 다르거나 (다른 도구가 고쳤다) 없어졌으면 쓰지 않고 [덮어쓰기] 를 보인다. 이 창이 쓴 바이트를 다음 base 로
   기억한다 (팩 DB 의 원문은 다시 읽기 전까지 옛것이다)
6. 저장 전 검사 = [적용] 과 같은 콘텐츠 로더 검사. 오류면 쓰지 않고 [오류가 있어도 저장] 을 보인다 (고치는 중의 글도 남길 수 있게 —
   다음 로드가 실패한다는 것을 사람이 고른다)
7. 팩에 없던 파일 (오버레이로 더한 id) 은 폴더까지 만든다
```

## 근거

```text
- 두 단추: 오버레이 (팀 · 월드 단위, 되돌릴 수 있음) 와 파일 (프로젝트 단위, git) 은 쓰임이 다르다 — 하나로 묶으면 어느 쪽이 바뀌는지 모른다
- DocumentService: ADR-0109 "UI 는 파일을 직접 쓰지 않는다" · 원자적 쓰기 · 바깥 변경 대조를 이미 갖췄다
- 줄 끝: 저장 왕복이 파일을 바꾸지 않아야 한다 (ADR-0128 5) — 바꾸지 않은 줄까지 git diff 에 나오면 안 된다
- 오류 저장 허용: 자동 저장 · 편집기 관례 — 막으면 고치는 중의 글을 잃는다. 대신 묻는다
```

## 결과

- 얻는 것: 스크립트를 Studio 안에서 팩 파일까지 (16 KB 넘는 파일도), CRLF 파일의 줄 끝 보존, 바깥 변경 보호, 새 파일, 저장 → 다시 읽기 왕복 시험.
- 포기하는 것: 저장한 팩 파일을 지금 DB 에 다시 읽기 (월드 다시 열기 · [적용] 으로), 다른 파일의 저장 (DocumentService 로 여는 일반 편집기 —
  [계획]), 저장 후 오버레이 자동 정리, 파일 감시 (OS 알림 — 저장 때 대조만).
- 위험: 같은 파일을 다른 Studio 창 · 도구가 동시에 고치면 마지막 덮어쓰기가 이긴다 (덮어쓰기는 사람이 고른다).

## 대안

| 대안 | 기각 사유 |
|------|-----------|
| [적용] 이 파일까지 쓴다 | 원격 서버 · 다른 팀원의 월드 편집이 내 프로젝트 파일을 바꾼다 — 쓰임이 다르다 |
| 편집기 글을 그대로 쓴다 (줄 끝 무시) | CRLF 파일이 섞인 줄 끝이 된다 — 저장 왕복이 파일을 바꾼다 |
| 오류면 저장 거절 | 고치는 중의 글을 남길 수 없다 |
| DocumentService 를 되돌리기 줄에 | 저장 한 번이 Ctrl+Z 한 칸이 되어 월드 되돌리기와 섞인다 — 편집기 칸의 되돌리기와도 겹친다 |

## 재검토 조건

일반 파일 편집기 (DocumentService 문서 탭), 파일 감시, 저장 뒤 DB 다시 읽기 (Hot Reload 와 같은 길 — 25 · ADR-0066), 팩 git 통합.

참고 (ADR-0130 측정 고침): ADR-0130 의 Debug 분석 "5,000 줄 0.8 초" 는 시험 파일이 6,544 줄이던 때의 값 — 5,000 줄은 0.56 초 (쉬는 프레임 2.3 ms ·
타자 프레임 3.6 ms, test_script_assist).
