# ADR-0125. 함수별 스크립트 프로파일 — 프레임이 바뀔 때 자기 연료를 나눈다, ServerStats 함수 표 (프로토콜 18)

- 상태: **Accepted** · 날짜: 2026-11-11
- 관련: [ADR-0068](0068-script-profile-injected-diagnostic-clock-serverstats-protocol-14.md) (시스템 프로파일 · 프로토콜 14),
  [ADR-0124](0124-bytecode-line-table-format-11.md) (줄 표), [19-SANDBOXSCRIPT](../19-SANDBOXSCRIPT.md) 22장, [08-NETWORK](../08-NETWORK.md) 5장,
  task-registry M6-T4 (조각 2 — "프로파일 합 = 시스템 연료")

## 맥락

스크립트 프로파일은 시스템 단위였다 (ADR-0068 — 호출 · 연료 · 시간). 시스템 하나가 느릴 때 어느 함수 (콜백 · 도움 함수 · 비교자) 가
연료를 쓰는지 알 수 없었다 (19 22장 [계획]).

## 결정

```text
1. 측정 단위 = 연료 (결정적), 시계가 아니다. vm::FunctionProfile {calls, selfFuel} — 인터프리터마다 함수 번호 표, 호출을 넘어 쌓인다
   (resetProfile). 자기 연료 = 그 함수의 프레임이 맨 위일 때 쓴 연료 (명령 · 내장 원소 비용 · Host 호출 비용)
2. 나누는 때 = 프레임이 바뀔 때만: 들어갈 때 (부른 쪽에), RET (끝나는 함수에), 호출 끝 (트랩 · 연료 끝이면 남은 프레임 맨 위에).
   실행 루프 (명령마다) 는 바뀌지 않는다. 그래서 호출 하나의 자기 연료 합 = CallResult::fuelUsed — 시험이 지킨다 (성공 · 재귀 · 트랩 ·
   연료 끝 · 깊이 넘침 · 내장 콜백)
3. 늘 켜 둔다 (스위치 없음) — sbx_bench 로 측정한 비용이 잡음 안이다 (아래)
4. 함수 자리 = 선언 자리: bc::Function 에 (줄, 열) — 형식 11 에 더한다 (형식 11 은 아직 배포 전 — ADR-0124 와 같은 판).
   "<팩 폴더>/scripts/a.ts:8:3 (onTick)". 선언 자리가 없으면 첫 명령의 자리
5. 어댑터: collectFunctionProfile — 팩들의 표를 자기 연료 큰 차례 (같으면 자리 글자) 로 상위 N 과 합. 서버 · 클라이언트 시스템 둘 다
6. 프로토콜 18: ServerStats 끝에 scriptFunctions varint (≤ 16) × {site str(192) · calls · fuel varint} · scriptFunctionFuel varint (합).
   누적 (창 차이 아님 — 함수 표는 몫을 본다). Studio "스크립트 프로파일" 창에 서버 · 클라이언트 함수 표 (자리 · 호출 · 자기 연료 · 몫 ·
   연료/호출), SandboxServer 끝 줄에 상위 5 개
```

## 근거

```text
- 연료 단위: 결정적 — 같은 리플레이는 같은 프로파일, 서버와 클라이언트를 견줄 수 있다. 시간은 시스템 단위로 이미 있다 (ADR-0068)
- 프레임 경계만: 명령마다 세면 실행 루프에 비용이 든다. 경계 나누기는 CALL · RET 때 덧셈 둘
- 샘플링 안 함: 연료가 이미 정확한 일의 척도 — 표본 오차가 없다
```

## 결과

- 얻는 것: 함수 단위 핫스팟 (콜백 · 비교자 포함), 합이 시스템 연료와 맞는 표, Studio · 서버 끝 줄 표시.
- 포기하는 것: 함수별 실제 시간 (연료와 시간의 비는 명령 종류마다 다르다 — 내장 · Host 는 연료가 적다), 포함 (inclusive) 연료 · 호출 그래프 [계획].
- 측정 (Release, sbx_bench --only script, 2026-11-11 — 같은 기계 · 다른 일이 도는 중이라 잡음 큼): 바꾸기 전 / 뒤 — script merge sort n=100000
  119.3 · 98.7 ms / 105.9 · 108.7 · 105.0 ms, sort(cmp) n=100000 77.9 · 68.5 / 72.3 · 71.5 · 72.7 ms, script.regen 18.1 · 18.8 / 17.2 · 16.9 ·
  16.8 ms/틱. 연료는 같다 (결정적). 차이는 잡음 안.
- 위험: 프로토콜 18 — 17 클라이언트는 접속하지 못한다 (늘 그렇듯 같은 판끼리).

## 대안

| 대안 | 기각 사유 |
|------|-----------|
| 명령마다 함수 계수기 | 실행 루프 비용 — 이득 없음 (경계 나누기와 같은 답) |
| 시계 샘플링 프로파일러 | 결정적이지 않다, 스레드 · OS 의존 (Simulation 은 시계를 보지 않는다 — 04) |
| 창 차이 (초당) | 함수 수가 많아 기준을 들고 다닐 비용, 몫 · 누적이 더 읽기 쉽다 |

## 재검토 조건

포함 연료 · 호출 그래프 (재생 디버거 ST-06-7), 함수별 시간이 필요할 때 (JIT/AOT — D-16).
