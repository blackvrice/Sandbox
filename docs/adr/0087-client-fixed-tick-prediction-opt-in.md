# ADR-0087. Client Fixed Tick · 클라이언트 예측 — 게임마다 선택 (network.model), 자기 개체만, 입력은 고정 Tick 프레임으로 묶는다

- 상태: **Accepted** · 날짜: 2026-11-02
- 관련: [22-RUNTIME-V2](../22-RUNTIME-V2.md) 4 · 6장, [ADR-0086](0086-runtime-architecture-v2.md), [08-NETWORK](../08-NETWORK.md) (스냅숏 · 보간 —
  지금 모델), [04-DETERMINISM](../04-DETERMINISM.md), [23-ROADMAP](../23-ROADMAP.md) (v0.7 RT-07-*)

## 맥락

지금 클라이언트는 서버 스냅숏을 보간해 그리고, 입력은 행동 명령으로 보낸다 (08). 턴제 · 보드 · 느린 전략 게임에는 충분하지만, 직접
조작 (액션 · 이동) 게임은 왕복 지연만큼 늦게 반응한다. 외부 엔진은 클라이언트가 서버보다 앞서 예측하고 스냅숏이 오면 다시 시뮬레이션
한다 (Unity Netcode for Entities — 22 12장 [N1]). 다시 도는 틱 수가 커지면 CPU 핫패스가 된다는 것도 같은 문서가 적는다.

## 결정

```text
1. 게임 매니페스트 network.model = "snapshot" (기본 — 지금 그대로) | "predicted". lockstep 은 두지 않는다. v0.5 M2-T7 이 자리만 예약
   ("snapshot" 만 받는다), "predicted" 는 v0.7 에서 받는다
2. Client 고정 Tick = 서버 tickRate 와 같은 주기 (지금 30 Hz), Main 스레드의 누산기 (프레임마다 0 ~ 5 번, 넘으면 버리고 계측) — 렌더 FPS 와
   따로, 새 스레드 없음. predicted 게임에서만 돈다
3. 입력은 고정 Tick 마다 InputFrame { tick, 행동 비트 · 양자화된 축 } 하나 — 패킷에 마지막 3 개를 겹쳐 보낸다. 키 이벤트마다 패킷을 보내지
   않는다. 서버는 tick 창 (너무 옛 · 너무 미래 거절) · 속도 검사 뒤 executeTick 에 적용하고 ack 를 스냅숏에 싣는다 (새 프로토콜 번호 —
   15 다음)
4. 예측 대상 = 이 플레이어가 소유한 (game.owner) 그리고 net.predicted 표시가 있는 개체만. PredictedWorld (ClientWorld 와 따로) 에서
   서버와 같은 Movement · Collision 코드로 돈다 — 클라이언트 전용 물리 구현 금지. 원격 개체는 보간 그대로
5. 맞춤: 스냅숏 (tick T, ack T) 이 오면 예측 개체를 서버 값으로 두고 T+1 ~ 지금을 다시 돌린다. 상한 = 지연 / 틱 + 2 틱 (넘으면 바로 맞춤),
   오차 (위치 · 횟수 · 다시 돈 틱) 를 계측
6. 예측 결과는 서버로 가지 않고 권위가 아니다 — WorldHash · 골든 · 리플레이에 닿지 않는다. 대신 "같은 스냅숏 열 + 같은 입력 → 같은 예측"
   을 시험한다
```

## 선택지

| 안 | 내용 | 판단 |
|----|------|------|
| A (채택) | 게임마다 선택 · 자기 개체만 예측 · 고정 Tick 입력 프레임 | 턴제 게임은 비용 0, 액션 게임만 비용 |
| B | 모든 게임 · 모든 개체 예측 | 다시 돌리는 비용이 개체 수에 비례 — 50k 목표 (14) 와 충돌 |
| C | lockstep (입력만 주고받음) | 권위 서버 · 늦은 입장 · 관전과 맞지 않는다 |
| D | 키 이벤트마다 즉시 전송 | 패킷 수가 입력 수에 비례 · 순서 · 잃음 처리가 고정 Tick 과 어긋난다 |

## 결과

- v0.5 의 게임 (오목 · HUD 데모 · 템플릿) 은 snapshot 그대로 — 영향 없음.
- v0.7 에서 프로토콜 · 매니페스트 · 클라이언트 스케줄러가 늘고, 예측 오차 · 다시 돈 틱 수가 성능 문서 (14) 의 새 항목이 된다.
- 위험: 서버와 클라이언트의 Movement 코드가 같아도 부동소수 결과가 플랫폼마다 다를 수 있다 — 예측은 권위가 아니라 맞춤으로 흡수
  (오차 계측으로 확인), 결정론 보장은 서버만 (04 그대로).
