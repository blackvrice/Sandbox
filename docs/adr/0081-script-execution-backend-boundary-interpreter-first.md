# ADR-0081. 스크립트 실행 경계 — Interpreter 를 유지하고 IScriptExecutor 계약을 둔다, 함수별 프로파일은 v0.5, JIT/AOT 는 v1.x 검토

- 상태: **Accepted** · 날짜: 2026-10-28
- 관련: [20-CREATOR-ALPHA](../20-CREATOR-ALPHA.md) 6장, [ADR-0056](0056-sandboxscript-language-subset-own-compiler-no-gc.md) (언어 · 자체 컴파일러),
  [ADR-0058](0058-bytecode-register-machine-typed-registers-verifier.md) (바이트코드 · 검증기), [ADR-0064](0064-script-budgets-tick-fuel-disable-after-traps-saved-state.md)
  (예산), [ADR-0068](0068-script-profile-injected-diagnostic-clock-serverstats-protocol-14.md) (프로파일), 04 · 14 7.13

## 맥락

스크립트는 검증된 바이트코드를 인터프리터가 돈다 (연료 · 메모리 · 깊이 예산). 측정: 개체 하나의 읽기 + 쓰기 약 1 µs (14 7.13 —
10k 매 틱 9.93 ms). 장래에 JIT · AOT 를 넣을 수 있게 하라는 요청이지만 v0.5 의 필수로 만들지는 말라는 조건이다. 결정론 (onTick) ·
보안 (외부 제작자의 코드) · 플랫폼 (JIT 을 막는 곳) 을 지켜야 한다.

## 결정

```text
1. 실행 계약 IScriptExecutor: 모듈 하나를 받아 함수를 부른다 (인자 · 결과 · 트랩 · 쓴 연료 · 메모리). 지금 구현은 Interpreter 하나 —
   v0.5 에 인터페이스만 꺼내고 (M6-T4) 동작은 그대로 (골든 · 보호 시험 그대로)
2. onTick (server — 시뮬레이션): 다른 실행자는 Interpreter 와 비트 단위로 같은 결과 · 쓰기 · 트랩 · 연료를 내야 한다. 연료는 바이트코드
   기본 블록 기준 (실행 방식과 무관한 양). f64 는 IEEE 그대로 (FMA 금지 · 정밀도 확장 금지 · NaN 정규화), i32 는 감싸기 — 04 의 규칙
3. onUpdate (client — 표시): 결과만 같으면 된다 (결정론 밖). JIT 의 첫 후보는 여기
4. 보안: 패키지는 소스 (.ts) 만 담는다 — 네이티브 코드 · .dll · 기계어를 받지 않는다. JIT 은 엔진이 만든 코드만 (W^X — 쓰기와 실행을
   동시에 허락하지 않는다), 플랫폼이 JIT 을 막으면 Interpreter 로. AOT 는 플랫폼이 서명한 빌드에서만 (v1.x 검토 — 제작자 PC 의 AOT 는
   하지 않는다)
5. 프로파일 (v0.5 M6-T4): 인터프리터의 함수마다 호출 수 · 연료 계수기 (끄면 비용 없음), Host 호출마다 시간 (진단 시계 — ADR-0068).
   "스크립트 프로파일" 패널 · 서버 끝 줄 · sbx test 보고. 이것이 JIT 판단의 입력 — "VM 이 틱 · 프레임의 큰 몫이고 Host 경로 최적화로
   모자란다" 가 측정으로 보일 때만 v1.x 에 JIT 을 시작한다
6. 예산 (연료 · 메모리 · 깊이 · 호출 · 구조 변경 상한) 은 실행자와 무관한 엔진의 규칙 — 어떤 실행자도 우회하지 않는다
```

## 근거

```text
- 인터페이스만 지금: 계약 (결정론 · 연료) 을 먼저 고정하면 나중의 실행자를 같은 시험 (골든 · 보호 · 퍼즈) 으로 판정할 수 있다
- 측정 먼저: 지금 비용의 대부분이 Host 경로 (값 펼치기 · 쓰기 버퍼) 일 수 있다 — JIT 은 VM 명령만 빠르게 한다
- 소스만 받기: 외부 제작자의 네이티브 코드는 검증할 수 없다
```

## 결과

- 얻는 것: 장래 실행자가 들어올 자리와 판정 기준, v0.5 의 함수별 프로파일 (제작자 디버깅에도 쓴다).
- 포기하는 것: v0.5 의 실행 속도 향상 (없음).
- 위험: 실행자 경계를 꺼내는 리팩터링이 인터프리터 성능을 떨어뜨릴 수 있다 — script.regen 벤치로 회귀를 본다 (14).

## 대안

| 대안                                      | 기각 사유                                                                   |
|-------------------------------------------|-----------------------------------------------------------------------------|
| v0.5 에 JIT                               | 결정론 · 보안 · 플랫폼 검증이 크다 — 측정 근거도 아직 없다                   |
| 제작자 PC 에서 AOT (C++ 로 바꿔 컴파일)    | 네이티브 코드를 배포하게 된다 — 검증 불가, 플랫폼마다 빌드                   |
| WASM 런타임으로 갈아타기                  | 새 큰 의존 · 지금 바이트코드 · 검증기 · Host 계약을 다시 — 이득이 측정되지 않았다 |
| 계약 없이 나중에                           | 장래 실행자의 판정 기준이 없다 — 결정론 회귀를 찾기 어렵다                   |

## 재검토 조건

프로파일에서 VM 명령이 틱 · 프레임의 큰 몫으로 보일 때, 콘솔 · 모바일 같은 JIT 금지 플랫폼을 지원할 때 (AOT 검토).
