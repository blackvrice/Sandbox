# ADR-0106. 게임 UI scroll — 세로 밀기는 클라이언트 층의 상태, 휠은 포인터 아래 가장 안쪽 scroll 이 쓰고, 키보드 포커스는 가려지면 보이게 민다

- 상태: **Accepted** · 날짜: 2026-11-09
- 관련: [ADR-0103](0103-game-ui-input-controls-var-state-focus.md) (포커스 · 키), [ADR-0105](0105-game-ui-dropdown-tabs-index-var-overlay-list.md)
  (고르기 — 5 의 ScrollView), [ADR-0079](0079-game-ui-runtime-declarative-documents-renderer-adapter.md) (배치 · clip),
  [20-CREATOR-ALPHA](../20-CREATOR-ALPHA.md) 2.6 (NG-06)

## 맥락

NG-06 의 ScrollView. 배치는 헤드리스 · 결정적이고 (같은 입력 = 같은 정수 사각형), 넘친 자식은 clip 으로 자르기만 했다 ("스크롤은
[계획]"). 휠은 지금 게임 (카메라 확대) 의 것이다. 키보드 포커스 (Tab · 방향) 는 화면 밖 자식에 갈 수 있다.

## 결정

```text
1. 요소 "scroll" = panel 과 같은 키 (stack · gap · padding · align · children) — 컨트롤이 아니다 (포커스 · 이벤트 없음). 세로만
   (가로 밀기는 [계획]). size (또는 늘인 앵커) 로 보이는 높이를 정해야 밀 것이 생긴다 — 내용에 맞추면 범위 0
2. 밀기 상태 = 클라이언트 층 (GameUiLayer) 의 것 — 노드 · list 번호마다 픽셀 수 (배율을 곱한 배치 단위). var 가 아니다 (스크립트 ·
   서버가 알 일이 아니다). 문서 원문이 바뀌면 잊는다. 배치가 0 ~ 범위 (내용 높이 - 안쪽 높이) 로 자르고 정수 픽셀로 반올림한다
3. 배치: 자식의 부모 사각형을 밀린 만큼 위로. clip 은 scroll 의 사각형 (가려진 자식은 그리지 · 누르지 않는다 — 기존 clip 규칙).
   UiLayoutNode 에 scroll · scrollRange
4. 휠: 포인터 아래 가장 안쪽의 밀 수 있는 scroll (층 차례 modal → menu → hud, modal 이 보이면 modal 의 것만) 이 한 칸에 40 (× 배율)
   만큼. 범위 끝이어도 휠을 쓴다 — 앱은 그 프레임 휠을 게임 (카메라 확대) 에 주지 않는다
5. 포커스가 Tab · 방향으로 옮겨 가면, 가장 안쪽 scroll 에서 가려진 만큼 민다 (위로 가려졌거나 보이는 높이보다 크면 위를 맞추고,
   아래로 가려졌으면 아래를 맞춘다). 다음 배치부터 보인다
6. 그리기: panel 처럼 + 밀 것이 있으면 오른쪽 막대 (너비 4 × 배율, 손잡이 높이 = 보이는 비율 · 너비 두 배 이상) — 모든 노드 뒤에
   (자식이 덮지 않게). 막대 끌기 · 가로 밀기 · 겹친 scroll 의 바깥까지 보이게 하기 · dropdown 목록 밀기는 [계획]
```

## 근거

```text
- 층의 상태: 밀기는 보는 사람의 것 (같은 화면의 두 사람이 다르게 민다) — var 표 (256 키 상한) 를 쓰지 않는다
- 배치에 넣기: 밀린 자식의 사각형이 곧 라우팅 · 그리기 · 포커스 방향의 사각형 — 따로 옮기는 길이 없다. 결정적 (정수 픽셀)
- 휠을 끝에서도 쓰기: 목록을 끝까지 내린 뒤 한 번 더 굴리면 카메라가 확대되는 것은 뜻밖이다
```

## 결과

- 얻는 것: 긴 목록 · 설정 · 도움말을 정해진 칸 안에, 휠 · 키보드로.
- 포기하는 것: 막대 끌기, 끌어서 밀기 (터치), 부드러운 밀기 (애니메이션 — 결정적 배치는 한 번에), 가로 밀기.
- 위험: 겹친 scroll 은 가장 안쪽만 포커스에 맞춰 민다 (바깥은 [계획]).

## 대안

| 대안                                   | 기각 사유                                                                 |
|----------------------------------------|---------------------------------------------------------------------------|
| 밀기를 var 바인딩으로                   | 스크립트 · 다른 컨트롤이 쓸 일이 없는데 var 표 자리를 쓴다                  |
| 그리기에서만 옮기기 (배치는 그대로)      | 라우팅 · 포커스가 옮긴 자리를 따로 알아야 한다 — 두 길이 어긋난다          |
| 범위 끝에서는 휠을 게임에                | 목록 끝에서 한 칸 더 굴리면 카메라가 확대된다                                |

## 재검토 조건

게임패드 (I5 — 오른 스틱 밀기), 터치 입력, dropdown 목록이 화면을 넘는 경우 (밀기를 목록에도).
