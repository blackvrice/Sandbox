# ADR-0104. 게임 UI 글자 칸 — 글은 클라이언트 var 에만, 신호는 길이 (코드 포인트 수), 클릭은 어느 층이든 포커스, 스크립트는 ctx.uiVar · uiVarText

- 상태: **Accepted** · 날짜: 2026-11-09
- 관련: [ADR-0103](0103-game-ui-input-controls-var-state-focus.md) (입력 컨트롤 — 이 ADR 이 4 를 일부 바꾼다),
  [20-CREATOR-ALPHA](../20-CREATOR-ALPHA.md) 2.6 (NG-06), [27](../27-SCRIPT-IDE.md) 9장 (IME 조합 규칙),
  [19-SANDBOXSCRIPT](../19-SANDBOXSCRIPT.md) (client Host API)

## 맥락

NG-06 (2) 는 게임 UI 에 글자 칸 (TextInput — 한 줄 · 여러 줄 · 최대 길이 · IME) 을 더한다. ADR-0103 의 컨트롤은 값을 클라이언트의 var
표에 쓰고 바뀜을 신호로 알린다. 신호의 값은 i32 라 글을 서버에 보내지 못한다 — 문자열 신호는 새 명령 · 와이어 포맷 (프로토콜 16 → 17)
· 길이 상한 · 서버 필터가 필요하다. client 스크립트는 var 를 쓸 수 (setUi · setUiText) 있지만 읽지 못했다. 플랫폼은 확정된 글자만
(PlatformEvent TextInput — 창의 글자 입력이 켜졌을 때) 주고, 조합 창은 OS · 입력기가 그린다 (위치를 정하는 API 는 없다).
ADR-0103 4 는 hud 클릭이 포커스를 주지 않게 했다 (게임 키를 빼앗지 않으려고).

## 결정

```text
1. 요소 "textinput": value = "var:<키>" (U4 — 글은 var 의 글자, 컨트롤이 쓴다), placeholder? (빈 칸일 때 흐리게 — "@<키>" 도),
   maxLength? (1 ~ 256 코드 포인트, 기본 64 — 바이트는 1 KiB 까지), multiline? (참거짓), on.change = 신호만, disabled · tabIndex.
   글은 클라이언트의 var 표에만 있다 — 서버에 가지 않는다
2. on.change 신호의 값 = 글의 코드 포인트 수. 보낼 때: 한 줄 칸에서 Enter (같은 글이라도 — 채팅의 같은 말 두 번), 포커스가 떠날
   때 (Tab · Esc · 다른 곳 클릭) 포커스를 받은 뒤 · 마지막으로 보낸 뒤 글이 바뀌었으면. 글은 스크립트가 var 로 읽는다 (4)
3. 글자 칸은 어느 층 (hud 포함) 이든 누르면 포커스를 받는다 — 누르는 것이 곧 글을 쓰겠다는 것 (ADR-0103 4 의 예외). 편집 중에
   다른 곳을 누르면 놓는다. 캐럿은 끝에 (누른 자리로 옮기기는 [계획])
4. client Host API: ctx.uiVar(key): number (수 · 참거짓 1 · 0, 글자 · 없음 0), ctx.uiVarText(key): string (글자, 수는 보이는 글자,
   없음 "" — 1 KiB 까지). 지난 프레임까지의 표 (이 프레임의 setUi 는 프레임 뒤). Capability Ui · Read — 더하기만 (Host API 버전 1)
5. 편집 키 (UiKey 에 Backspace · Delete · Home · End): 왼 · 오른 = 캐럿 (끝에서도 다른 컨트롤로 가지 않는다), 위 · 아래 =
   multiline 의 줄 (첫 · 끝 줄 · 한 줄 칸이면 ADR-0103 5 의 탐색), Home · End = 줄의 처음 · 끝, Enter = multiline 은 줄 바꿈.
   Space 는 글자 (앱은 글자 칸 편집 중 Space 를 누르기로 바꾸지 않는다). 확정 글자를 그 프레임의 키보다 먼저 넣는다
6. IME: 글자 칸 편집 중 앱이 창의 글자 입력을 켜고 (남이 켠 것 — ImGui 칸 · F2 — 은 끄지 않는다), 조합이 끝난 글자만 넣는다 (27
   9장 — 조합 중 글은 문서에 넣지 않는다). 조합 창의 위치 (캐럿 자리) 는 [계획] — 창 API (Win32 ImmSetCompositionWindow ·
   Wayland set_cursor_rectangle) 가 필요하다
7. 문자열 신호 (글을 서버로 — 채팅 · 이름) 는 이 ADR 밖 [계획] — 새 명령 · 프로토콜 · 상한 · 서버 필터를 정하는 ADR 로
```

## 근거

```text
- 글을 var 에만: 프로토콜 · 서버 판정을 바꾸지 않고 글자 칸을 쓸 수 있다 (검색 칸 · 이름 표시 · 메모 · client 스크립트가 쓰는 설정).
  서버가 글을 알아야 하는 기능 (채팅) 은 7 의 결정 뒤
- 신호의 값 = 길이: 신호만 쓰는 길 (N1 — 서버가 판정) 을 지키며 "보냈다 · 비었다" 를 서버가 알 수 있다 (perTick · 범위로 판정)
- hud 클릭 포커스: 글자 칸은 포커스가 없으면 쓸모가 없다. 버튼 · checkbox 와 달리 누르는 순간 키보드를 원한다는 뜻이 분명하다
- 줄은 '\n' 으로만 (감싸지 않음): 캐럿 · 줄 이동 · 밀기가 단순하고 결정적 (헤드리스 시험 — 재기는 ITextMeasure)
```

## 결과

- 얻는 것: 한 줄 · 여러 줄 글자 칸 (편집 · 상한 · 한글 IME 확정 글자), 스크립트가 컨트롤 값을 읽는 길 (uiVar · uiVarText).
- 포기하는 것: 글을 서버에 보내기 (7), 선택 · 복사 · 붙여넣기 · 누른 자리 캐럿 · 깜빡이는 캐럿 · 감싸기 ([계획]), 조합 창 위치.
- 위험: 글자 칸 편집 중에는 게임 키가 모두 막힌다 (Esc · 다른 곳 클릭으로 놓는다 — hud 글자 칸을 두는 게임은 이것을 알아야 한다).

## 대안

| 대안                                       | 기각 사유                                                                 |
|--------------------------------------------|---------------------------------------------------------------------------|
| 지금 문자열 신호 (프로토콜 17)               | 길이 · 필터 · 속도 제한 · 리플레이를 함께 정해야 한다 — 글자 칸 자체와 따로 |
| 글자 칸 상태를 GameUiLayer 안에만            | 스크립트가 읽지 못한다 (ADR-0103 1 과 같은 이유)                             |
| hud 글자 칸도 Tab 으로만 포커스              | 마우스로 채팅 · 검색 칸을 누르는 흔한 쓰임이 막힌다                          |
| 신호 값 = 1 (보냈다만)                       | 빈 글 보내기를 서버가 가려내지 못한다                                       |
