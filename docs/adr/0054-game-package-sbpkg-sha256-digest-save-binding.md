# ADR-0054. 게임 패키지 = 파일 하나 (.sbpkg — 색인 + 파일, SHA-256 다이제스트, 압축 · 서명 없음), 세이브는 게임에 묶인다 (D-02)

- 상태: **Accepted** · 날짜: 2026-10-20
- 관련: [ADR-0040](0040-game-project-manifest-world-is-save-folder.md) (프로젝트 · 월드 = 세이브 폴더), [ADR-0043](0043-sbx-project-tool-new-from-scenario-template.md)
  (sbx), [ADR-0044](0044-project-saves-root-is-worlds-ctrl-s-entry-world.md), [09-SERIALIZATION](../09-SERIALIZATION.md) 3 · 9장,
  [15-BUILD](../15-BUILD.md) 7장, [18-PLATFORM](../18-PLATFORM.md) 5.1 · 6.1 (D-02), [플랫폼 초안 architecture/02](../platform/architecture/02_GAME_PACKAGE_FORMAT.md)

## 맥락

v0.2 M5-T2 "GamePackage 빌드 · 로드 (D-02: 형식 · 다이제스트), SaveGame 결속 (패키지 다이제스트 · 게임 버전)". 지금 게임을 남에게
주려면 프로젝트 폴더를 통째로 넘겨야 하고 (편집용 세이브 · 빌드 산출물까지), 받은 쪽이 파일이 바뀌었는지 알 수 없다. 세이브는 어느
게임의 것인지 모른다. 초안 02 5 · 6 · 7장: 파일별 SHA-256, content digest, 수정된 파일은 로드 거부, 같은 프로젝트 두 빌드의 digest
동일, SaveGame 은 패키지 digest 에 결속. 열린 결정 D-02 = 직렬화 · 서명 · 압축. 정할 것:

```text
1. 형식 (폴더 · zip · 자체 컨테이너)     2. 무엇을 담나          3. 다이제스트 · 재현성       4. 압축 · 서명
5. 여는 길 (검증 · 풀기 · 실행)          6. 세이브 결속
```

## 결정

```text
1. 파일 하나 .sbpkg — 자체 컨테이너 (외부 라이브러리 없음, 작은 끝):
     magic "SBXPKG\0\n" · format u32 (= 1) · indexBytes u64 · index (JSON, 키 정렬) · 파일 바이트를 index 순서로 빈틈없이
   index = {format, gameId, name, version, engine, entryWorld, gameMode, digest, files: [{path, size, sha256, offset}]}.
   path 는 프로젝트 기준 상대 경로 (project::checkRelativePath 규칙 — '/' · [A-Za-z0-9_.-] · "." ".." 없음), 바이트 순 정렬 ·
   겹침 없음. 상한: 파일 65536 개, 패키지 2 GiB (지금은 한 번에 읽는다), index 16 MiB.
2. 담는 것 = 실행에 필요한 것만: sandbox.project.json, 프로젝트 콘텐츠가 읽은 팩 (requires 포함 — 폴더째, presentation/ 포함),
   시작 월드 폴더. 다른 worlds/ (편집 세이브) · build/ · 그 밖의 파일은 담지 않는다. 빌드 전에 openProject 와 같은 검사 —
   오류면 만들지 않는다. 바이트코드 · 에셋 cook · SBOM · 락 파일은 v0.3 · v0.4 [계획].
3. 파일마다 SHA-256 (foundation/hash/Sha256 — FIPS 180-4), digest = SHA-256("<sha256> <size> <path>\n" 를 path 순으로).
   시각 · 순서 · 압축이 들어가지 않아 같은 프로젝트 (같은 바이트) 의 두 빌드는 같은 파일이다. 줄 끝을 바꾸지 않는다 —
   다른 체크아웃(CRLF)이면 digest 가 다르다 (초안 "빌드 환경 고정 시").
4. 압축 없음 · 서명 없음 (v0.2). 압축 (zstd) 은 패키지가 커질 때 format 2 로, 서명은 레지스트리가 생길 때 (v0.6 Hub — 신뢰
   루트가 필요하다) [계획]. 지금의 SHA-256 은 무결성 (고침 · 깨짐) 확인이지 출처 증명이 아니다.
5. 여는 길: 헤더 · index 모양 → 파일마다 SHA-256 → digest. 하나라도 다르면 거절 (고친 패키지는 열지 않는다). 그 뒤
   <임시>/sbx-packages/<digest 앞 16>/ 에 풀고 project::openProject — 서버 · 클라이언트 --world 가 .sbpkg 를 받는다
   (scenario::openWorldSource). 같은 digest 가 이미 풀려 있으면 파일마다 다시 확인하고 쓴다 (다르면 다시 푼다).
   세이브 폴더 기본값 = <패키지 폴더>/<이름>-saves (풀어 둔 캐시가 아니다). 도구: sbx build <폴더> [--out] ·
   sbx check <파일.sbpkg> (검증 + 풀어서 프로젝트 검사).
6. 세이브 결속: 게임 프로젝트 · 패키지를 돌리는 서버가 저장하면 world.json 에 "game": {gameId, version, package?} (package =
   패키지 digest — 프로젝트 폴더로 돌렸으면 없음). 선택 키라 worldVersion · schemaVersion 그대로 (옛 엔진은 무시한다).
   서버의 불러오기: 다른 gameId 의 세이브는 거절, 다른 version · package 는 열고 결과에 알린다 ("버전 0.1.0 에서 저장" ·
   "다른 패키지 빌드에서 저장"), 묶이지 않은 세이브는 그대로. 세이브 마이그레이션 (게임 버전 간) 은 [계획].
```

## 근거

```text
- 자체 컨테이너: zip 은 압축 · 확장 필드 · 시각이 끼어 재현성을 지키려면 라이브러리를 고쳐 써야 하고, 의존을 늘린다. 색인 +
  이어 붙인 바이트는 100 줄 남짓이고 검증 규칙을 정확히 말할 수 있다.
- 담는 것을 좁게: 편집 세이브 · 빌드 산출물이 섞이면 같은 게임의 digest 가 매번 달라지고 크기가 커진다.
- 풀어서 연다: 콘텐츠 로더 · 세이브 로더 · 재시작이 모두 폴더를 읽는다. 가상 파일 시스템은 같은 검사를 두 번 만든다.
  digest 로 캐시하면 다시 열 때 풀지 않는다.
- 결속은 경고 위주: 같은 게임의 다른 버전 세이브를 막으면 업데이트 뒤 진행을 잃는다 (마이그레이션 전까지 알리는 것이 낫다).
  다른 게임의 세이브는 콘텐츠가 맞아도 뜻이 다르므로 막는다.
```

## 결과

- 얻는 것: sbx build 로 게임 하나 = 파일 하나, 고친 파일 거절, 같은 프로젝트 = 같은 바이트, --world <패키지> 로 서버 · 싱글플레이.
  세이브가 어느 게임 · 버전 · 빌드의 것인지 안다.
- 포기하는 것: 압축 · 서명 · 흐름 읽기 (2 GiB 한 번에), 원격 클라이언트가 패키지를 받는 길 (지금은 --content <폴더> — v0.7 Directory), 다른 worlds 담기.
- 위험: 임시 폴더의 캐시가 쌓인다 (digest 마다 하나 — 지우기 도구는 [계획]). 2 GiB 넘는 게임은 못 만든다.

## 대안

| 대안                                  | 기각 사유                                                                     |
|---------------------------------------|-------------------------------------------------------------------------------|
| zip (.sbpkg = zip)                    | 라이브러리 의존 · 시각 · 압축 옵션이 재현성을 깬다, 이름 인코딩 문제          |
| 폴더 그대로 + digest 파일             | 파일 하나로 주고받을 수 없다, 폴더에 섞인 파일을 막기 어렵다                  |
| 시작 때 압축 (zstd)                   | 지금 게임은 수백 KB — 의존을 늘릴 이유가 없다 (format 2 로 더할 자리를 둔다)  |
| 서명 (키 쌍) 을 지금                  | 신뢰할 공개 키를 나눠 줄 곳 (레지스트리) 이 없다 — 이름만 서명                 |
| 메모리에서 바로 실행 (풀지 않음)      | 로더 · 세이브 · 재시작이 모두 폴더를 읽는다 — 가상 파일 시스템이 필요하다     |
| 다른 버전 세이브를 거절               | 업데이트하면 모든 진행을 잃는다 (마이그레이션 전까지)                          |

## 재검토 조건

패키지가 커질 때 (압축 · 흐름 읽기), Hub · 레지스트리 (서명 — v0.6), 패키지 관리자 (락 파일 · 의존 — v0.4), 스크립트 (바이트코드 —
v0.3), 원격 클라이언트가 패키지를 받아야 할 때 (v0.7), 세이브 마이그레이션 체인이 필요할 때.
