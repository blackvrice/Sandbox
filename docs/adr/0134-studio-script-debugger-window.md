# ADR-0134. Studio 스크립트 디버거 창 — 기록을 자기 콘텐츠로 디버그 재생, 중단점은 세션 사이에 남고 편집기 줄 번호 칸으로 놓는다

- 상태: **Accepted** · 날짜: 2026-11-12
- 관련: [ADR-0132](0132-script-debugger-brk-patch-local-names-format-12.md) (VM 쪽), [ADR-0133](0133-script-replay-debug-session-thread.md) (재생 세션),
  [ADR-0130](0130-script-editor-widget-imgui-input-assist-service.md) (편집기 위젯), [ADR-0108](0108-editor-services-target-command-table.md) (서비스 분리),
  [27-SCRIPT-IDE](../27-SCRIPT-IDE.md) 6 · 8장, task-registry ST-06-7 (조각 3)

## 맥락

재생 세션 (조각 2) 을 Studio 에서 쓰게 한다 — 기록 (start/ + replay.sbxr) 을 골라 디버그 재생, 중단점 · 단계 · 스택 · 지역 · 감시 · logpoint 를
창으로. 중단점은 스크립트 편집기 (콘텐츠 창) 에서 놓는 것이 자연스럽고, 멈춘 줄은 편집기에 보여야 한다. Studio 의 라이브 월드는 서버 (로컬 ·
원격) 의 것이고, 그 콘텐츠 DB 는 오버레이로 바뀐다.

## 결정

```text
1. editor/services/ScriptDebugService (UI 를 모른다): 기록 열기 = 리플레이를 읽고, 엔진 컴포넌트 카탈로그를 새로 만들고, 리플레이 머리의 팩을
   콘텐츠 폴더 (--content — 로컬 서버가 쓰는 것) 에서 loadContent, 시작 세이브를 loadWorld → ScriptDebugSession (Ready). 라이브 월드의
   콘텐츠 · 오버레이와 따로 (로컬 서버의 재생과 같은 입력 — 같은 해시)
2. 중단점 (팩, 파일, 줄, logpoint 글) 은 서비스가 갖는다 — 세션 사이 (처음부터 · 다른 기록 · 닫기) 에 남는다. 세션이 Ready · Paused 면 바로 넣고,
   재생이 돌거나 끝난 동안 바꾼 것은 미뤘다가 멈추면 (update — 프레임마다) · 처음부터에 넣는다. 놓인 BRK 수 0 이면 창이 "그 줄에 코드 없음"
3. editor/ui/ScriptDebugPanel ("스크립트 디버거" 창): 기록 고르기 · 열기 · 다시 찾기, 시작 (틱에서 멈춤) · 계속 · 한 줄 (Over) · 들어가기 (Into) ·
   나가기 (Out) · 그만 · 처음부터, 멈춘 자리 + [편집기에서 보기], 호출 스택 (고르면 그 프레임의 지역 · 감시 — 안쪽이 아닌 프레임의 감시는
   멈춤 · 프레임 · 식 수가 바뀔 때만 디버그 스레드에 묻는다), 지역 표, 감시 식 (더하기 · 빼기), 중단점 (빼기 · 손으로 놓기), logpoint 글, 끝나면
   재생 결과 (해시 기록 일치 · 끝 해시 · 다름 · 실패)
4. 편집기 (ScriptEditor) 의 줄 번호 칸: breakpointGutter 이면 누른 줄이 toggledLine 으로 나온다 (놓고 거두기는 부르는 쪽 — 콘텐츠 창이 서비스로).
   중단점 줄 = 빨간 점, 멈춘 줄 = 줄을 칠하고 ▶ · 처음 보일 때 그 줄로 스크롤. 진단 점은 칸의 오른쪽으로 옮겼다
5. [편집기에서 보기] = showScriptLine: 그 팩 · 파일의 오버레이 id 의 스크립트를 콘텐츠 창에서 고르고 (이미 고친 채 열려 있으면 글은 그대로) 그 줄로
   커서 (텍스트 위치 계약 offsetAt)
6. Studio: 보기 메뉴 · 명령 view.script-debugger, "scripting" 배치의 오른쪽 도크. 앱 설정의 savesRoot (기록을 찾는 곳 — --saves · 프로젝트
   worlds/) · contentRoot (main 이 넣는다)
7. 기록 이름 · 표시 경로는 UTF-8 (io::displayPath) — 한글 폴더 이름 (path::string() 은 코드 페이지라 던진다)
```

## 근거

```text
- 자기 콘텐츠로: 라이브 DB 를 빌리면 오버레이가 두 번 들거나 (세이브의 오버레이 + 라이브의 것) 서버가 DB 를 바꿀 때 세션 아래의 참조가 사라진다.
  로컬 서버의 재생과 같은 입력이어야 해시가 같다
- 중단점을 서비스에: 디버그 재생은 짧게 여러 번 (처음부터) 한다 — 놓은 자리를 다시 놓게 하지 않는다
- 줄 번호 칸 클릭: IDE 관례 (VS Code · Roblox Script Editor). 편집기 위젯은 디버거를 모른다 — 줄만 알린다 (위젯 · 서비스 분리)
```

## 결과

- 얻는 것: Studio 안의 재생 디버거 (G7 디버깅 게이트의 편집기 쪽), 편집기 중단점 · 멈춘 줄, 한글 기록 이름.
- 포기하는 것: 라이브 테스트 플레이에서 바로 멈추기 (기록 → 디버그 재생 두 걸음), 조건부 중단점 · 식 감시 (ADR-0132), 멈춘 틱의 월드 보기 ·
  되감기 (ADR-0133), 단축키 (F10 · F11 — 셸의 F5 와 겹침을 정리한 뒤), 마우스로 중단점 끄기 (지우기만).
- 위험: 기록의 팩이 지금 콘텐츠 폴더와 다르면 (고친 뒤) 시작 해시 · 해시 기록이 어긋난다 — 창이 "해시가 다르다" 를 보인다 (그때의 줄이 소스와 다를 수
  있다). 큰 기록의 열기는 UI 스레드에서 로드한다 (측정 뒤 비동기 [계획]).

## 대안

| 대안 | 기각 사유 |
|------|-----------|
| 라이브 월드의 콘텐츠 DB 를 빌린다 | 오버레이 · 수명 문제 (근거) |
| 테스트 플레이 중 라이브로 멈춘다 (방식 A) | 다른 클라이언트 · 틱 예산 (27 6장) |
| 중단점을 세션에만 | 처음부터마다 다시 놓아야 한다 |
| 편집기 위젯이 디버거 서비스를 직접 안다 | 위젯 · 서비스 분리가 깨진다 (ADR-0130) |

## 재검토 조건

테스트 플레이에서 한 번에 "기록하고 디버그" 요구, 큰 기록의 열기 시간, 단축키 정리 (셸 명령 표), 조건부 중단점.
